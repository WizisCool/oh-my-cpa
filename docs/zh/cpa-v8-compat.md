# CLIProxyAPI v8 集成契约

Oh My CPA 要求底层网关提供 **CLIProxyAPI（CPA）v8 及以上版本**的管理接口。网关支持 v8 接口与配置文件仍保持旧版 v7 YAML 格式是两件彼此独立的事（[英文原版](../cpa-v8-compat.md)）。

## 能力探测与插件协议边界

- **v8 门禁**：`internal/cpa/management/v8_gate.go` 通过校验配置版本接口的返回值来区分“版本过低（`cpa_v8_required`）”“管理接口未启用（`cpa_management_disabled`）”与临时网络故障。
- **插件多入口身份识别**：插件声明的 `oauth_provider_entries` 会映射为各自的登录卡片、品牌图标与发行凭据分组，同时以插件主图标作为回退，确保凭据列表、配额与请求日志中的显示一致。OAuth 登录报错信息经统一脱敏截断（去除回调参数、会话 ID、表单密钥与邮箱，最长 300 字符）后再展示。
- **插件商店多语言元数据**：目录中的标题与描述按控制台语言精准匹配并保留简繁体差异，未译字段自动回退至基础元数据，而插件 ID、来源信任等级与安装目标不受翻译字段影响。
- **旧版配置文件无损兼容**：仅读取或浏览页面不会改写 CPA 的旧格式 `config.yaml`；首次在控制台执行配置写入时，OMC 会先完整读取并加密保存原 YAML 备份（支持随时下载恢复），再委托 CPA 完成配置合并与结构升级。

## 读写语义与一致性保障

- **DTO 严格投影**：普通控制台接口返回手写白名单结构体，严格区分缺失、`null`、显式 `0` 与显式 `false`；明文密钥与认证文件仅通过带审计门禁的专用端点释放。
- **修订号校验与 250ms 写合并**：控制台外观层与 Agent 的配置编辑在服务端串行写锁下校验当前修订号与修改路径（冲突返回 `config_conflict`，校验失败返回 `config_rejected`），并在每次改写前自动保存一份加密快照；高频开关、标量与路由状态经 `StateCoordinator` 在 250ms 窗口内防抖合并写入（传递请求头 `X-OMC-Sync: 1` 可强制同步直写），而结构化整段配置保存与 Agent 写入前会自动排空挂起批次，保证修订号严格对齐。经由 OMC 代理的原生插件页面配置写入（`plugin_page_proxy`）同样受串行写锁与写前加密备份门禁约束，但保留 CPA 原生的后写覆盖（last-write）语义，不提供控制台外观层的修订号冲突校验契约（详见 [系统架构](../dev/architecture.md)）。
- **敏感词映射与 Claude 规则**：诸如 `sensitive-words-replace` 等用户自定义映射表按完整映射对象在对应配置路径更新，避免把任意短语直接拼接进 URL；连接复用池（connection pool）字段按凭据维度独立解析继承关系，保留显式 `false`/`0` 与空覆盖块语义。
- **多路径非原子变更坦诚回报**：涉及跨多个 CPA 接口的复合配置操作在写入前必须落盘加密备份；如中间某一步失败，直接如实回报状态而不虚构“事务回滚”。

## 凭据恢复与请求结构化证据

- **精确凭据定向重登**：针对单条凭据重新发起 OAuth 登录时，仅当网关确认支持对应生命周期字段且授权会话返回值核对一致后才放行登录链接，绝不会悄悄退化成新建随机账号登录。
- **结构化用量细节**：用量解码器按允许列表保留请求级扩展观测（模态统计、缓存 TTL 分档、工具调用详情、请求与实际观测图像参数、媒体计数及上游费用等）；超限或未知字段会将记录标为 `is_partial` 而不丢弃主记录，也不会与标准互斥 Token 口径混淆相加。

## 共存原则

安装 OMC 不会私自升级或改动已有 CPA 部署，连通性探活只做管理鉴权验证，**绝不弹出或消费 CPA 用量队列**。与其他管理面板混用时的注意事项见[安装指南](install.md#与其他管理面板共存)。
