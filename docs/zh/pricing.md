# 定价与费用核算

Oh My CPA（OMC）通过只增不改（append-only）的版本化价格表为每条请求核算估算费用，并非上游账单系统。每条请求在入库时锁定请求发生时刻生效的价格版本；后续更新目录价格、修改费率或更换凭据均不会篡改历史费用证据（[英文原版](../pricing.md)）。

## 价格匹配规则

OpenRouter 公开模型目录是唯一内置的自动拉取定价来源。OMC 以持久化保存的 CPA 模型目录作为当前可用模型与提供商依据，不用历史请求反推网关现状：

- **自动（Auto）**：仅在规范化名称完全安全命中时自动跟随 OpenRouter 目录价格。
- **关联（Linked）**：由管理员显式绑定至指定的 OpenRouter 条目。
- **自定义（Custom）**：保留人工输入的费率、阶梯规则与倍率，不受目录同步覆盖。

相似名称或附带推理强度后缀的猜测仅作参考建议，绝不会静默生效；存在歧义的 OAuth 别名亦不会盲目自动匹配。对于尚未自动命中的模型，系统会基于内置 `models.dev` 快照提供多家公开报价作为编辑参考，但同样只在管理员填入并保存为自定义价格后才生效。

支持为特定提供商渠道配置覆盖价格（Channel model price）与渠道倍率（Channel multiplier）。删除渠道独立价格时会写入墓碑版本，此后的请求回落使用通用模型价格，历史记录保持原貌。

## 阶梯计费与报价语义

所有单价以**每百万 Token 美元（USD）**定义。报价计算从匹配的一个阶梯规则出发，按精确分数应用模型与渠道倍率，最终统一半入法四舍五入至纳美元（USD nanos，对应实现在 `internal/pricing/quote.go` 与前端 `pricingDisplay.ts`）：

- **阶梯条件**：单条阶梯可同时约束服务等级（`service_tier`）、提示词长度阈值（Prompt size）与计费时段窗口。匹配优先级依次为：**服务等级规则 → 最高提示词阈值 → 时段规则 → 存储顺序**。不同阶梯之间互斥不叠加；需要同时约束长上下文与优先通道时应建为同一条复合阶梯。未单独覆盖的字段沿用基础费率，显式设 `0` 则保持免费。
- **时段窗口**：支持半开区间与跨午夜窗口，严格按请求发生时刻及阶梯自身的 IANA 计费时区判定（未配置时默认 UTC），不受浏览器本地或全局展示时区干扰。
- **服务等级（Service tier）**：按提供商语义解析。例如 Codex 以最终出站请求等级优先于客户端请求等级，显式 `auto` 不会错误穿透；其他情况优先采用上游响应报告的服务等级。`fast` 与 `priority` 不会擅自视作同义，按价格表声明匹配。
- 当 OpenRouter 缺省缓存读取费率时，导入器默认沿用其提示词输入价格，而非按零元免费计费。

## 费用快照与 Token 拆分

请求记录入库时在同一事务内写入命中的模型/渠道价格版本 ID、阶梯与最终纳美元金额。若缺乏有效定价或完整 Token 账务证据，请求保留为**未定价（Unpriced）**而非显示 `$0`，且汇总统计遇到部分未定价流量时会在界面明确提示其为局部金额（`≥ $…`）。

CPA 提供的结构化账务拆分会把输入划分为**未命中缓存输入、缓存读取、缓存写入**，把输出划分为**非推理输出与推理输出（Reasoning）**，避免重复计算推理 Token；缺少完整结构化拆分时退回兼容传统 Token 口径，发现无效字段则标为未定价保留原证而不做猜测。

历史聚合数据（`usage_facts`）会在明细过期后永久保留，所有展示货币折算仅发生在展现层，会计底账与费用分析始终锚定请求当时的美元快照。
