# Oh My CPA v0.3.24

This release reorganizes the plugin ecosystem and store around curated community
registries, retains granular request-failure classifications from CPA in diagnostics
and persistence, accelerates provider identity loading, and unifies deployment assets
with early startup checks. Credential refresh outcomes preserve unresolved classifications
with localized recovery guidance, and the currency feed cleanly skips unsupported non-ISO
quotes.

## Plugin store and ecosystem

- The managed plugin registry is decoupled to `omc-community/omc-plugins` and now
  distinguishes between the registry listing a plugin and the repository that maintains
  it. Listings display distinct origins: **OMC Official**, **OMC Community**,
  **CPA Official**, **CPA Community**, and **Third-party**.
- OMC Official plugins open the store in a dedicated featured section and install after
  a single confirmation, matching CPA Official extensions. Other listings, including
  OMC Community plugins, require typing the plugin ID to confirm installation.
- The store toolbar unites search, a source selector with per-source counts, installation
  status segments (All, Installed, Available), active tag filtering, and a filter reset.
  On mobile devices, filters collapse into an expandable disclosure.
- The store scales to large catalogs: each source previews six entries with a "View all"
  expansion, clicking any tag filters the store by that tag, and individual source
  failures display error banners scoped directly to the affected section.
- An inline switch in the store allows operators to re-enable the OMC plugin source
  directly when disabled.
- Opening plugin settings or the store automatically reconciles CPA configuration,
  silently removing the retired legacy OMC registry URL while preserving custom
  sources, their configured order, and current configuration revisions.
- The installed-plugins panel adds a running/stopped status filter and provenance
  indicators. The plugin configuration drawer opens with an identity header displaying
  state, provenance, and links, while modified fields render with a subtle washed row
  background.
- The documentation highlights the new ecosystem structure in the README and guides
  operators on plugin installation and source management.

## Request failure classifications and diagnostics

- Optional CPA request-level failure classifications (`fail.code`) are preserved through
  request decoding, forward-only SQLite storage, HTTP single-request projections, and
  Agent/MCP `requests_get` capability calls. The supported classification codes are
  `request_scoped` and `stream_truncated`.
- In the request overview drawer, explicit failure classification takes precedence over
  HTTP status code fallback. Diagnostics present localized classification names beside
  verbatim raw codes across all four locales (`zh`, `en`, `zh-Hant`, `ms`), while
  unclassified and historical requests remain unknown.
- Request failure popovers in the request list now wrap preformatted error bodies and
  unbroken strings, scrolling smoothly within a 220px height ceiling and restoring the
  HTTP status badge styling.
- Request totals, pricing logic, retry mechanisms, and credential policies remain strictly
  unaffected.

## Performance and credential recovery

- Provider identity loading is accelerated by reading independent provider families
  concurrently while preserving registry order, runtime credential attribution, and read
  fallbacks. In synthetic testing with 40ms upstream latency, catalog loading improved
  from 649ms to 82ms.
- Cached request-provider identities remain confirmed during background catalog
  refreshes, preventing unnecessary re-resolution races.
- CPA's allowlisted `refresh_outcome_unknown` classification and bounded HTTP status
  codes (400–599) are preserved across credential recovery summaries, HTTP DTOs, and
  Agent/MCP credential inspect tools. Unrecognized codes continue to map safely to
  `refresh_failed`.
- The credential drawer renewal details explain unresolved refresh results in all four
  locales and advise the operator to reauthenticate with the original account to obtain
  a new grant, while keeping credential tokens, messages, receipts, and internal journals
  isolated from exposure.

## Deployment and startup diagnostics

- Official Compose recipes are consolidated into `deploy/compose.full.yml`
  (CPA + OMC + updater) and `deploy/compose.omc.yml` (OMC + updater),
  eliminating duplicated inline configurations in READMEs and installation guides.
- Compose recipes default data storage to the `oh-my-cpa-data` named volume (pre-initialized
  in the container at `/data` owned by `10001:10001` with permissions `0700`), while
  preserving full support for host directory bind mounts (`OMCPA_DATA_PATH=./oh-my-cpa-data`)
  and UID/GID overrides (`user: ${OMCPA_USER:-10001:10001}`).
- Redundant environment variable overrides are removed from Compose templates where default
  binary and image values already apply.
- Go startup checks in `internal/app` now run `ensureDataDirWritable` before opening SQLite,
  emitting an immediate, actionable error if a host bind mount has mismatched ownership.
  Misleading Docker port conflict suggestions were replaced with clear listener address
  diagnostics for native and host-network deployments.

## Exchange rates

- Frankfurter v2 currency feeds that blend non-ISO crypto or metal instruments (such as
  `AAVE`, `USDC`, `HBAR`, or `BTC`) into the USD stream now skip non-display quotes rather
  than failing the entire snapshot refresh with `ErrFetchFailed`.
- USD remains the required base currency with an exact identity rate of 1.0, and all ten
  required display currencies continue to be strictly validated.

## Upgrade notes

- Back up `.env` and your SQLite database or volume before upgrading; refer to
  `docs/ops/sqlite-operations.md`.
- Database migration: version 058 adds the `fail_code` column to `usage_events`.
  SQLite applies migrations automatically on startup.
- Upgrading automatically retires the legacy OMC plugin registry URL from CPA
  configurations without affecting custom plugin sources.
- Existing Compose deployments with bind mounts continue to work without modification.
  New deployments follow the unified Compose templates with named volumes by default.
- Container images are available on Docker Hub as `wiziscool/oh-my-cpa:v0.3.24` and
  `wiziscool/oh-my-cpa:0.3.24`.
