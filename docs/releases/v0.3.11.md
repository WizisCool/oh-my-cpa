# Oh My CPA v0.3.11

This release lets an OAuth sign-in request its own proxy, selects every filtered
credential from one bar, gives the provider editor one action for a model's
thinking levels, and remembers the desktop rail's expansion. The dashboard's
model panels now focus a series by click with every other series left in view,
carry each model's maker mark and fit the whole ranking on the card. The
configuration editor exposes CPA's HTTP and Codex compression controls and
retires the discovery switch that stopped advertising management endpoints.
Request rows resolve the provider a call actually used instead of a display-name
guess, Model Square bounds the credential reads behind its directory,
and the affected-check plan reports a change in about a seventh of the time it
took.

## OAuth workspace

- Connect accepts an optional session-scoped proxy before authorization starts.
  The value travels only through OMC's `POST /management/oauth/start` and CPA's
  `POST /v8/management/oauth/auth-url` JSON body; leaving it empty keeps the
  existing GET path and CPA's default routing. CPA owns the authorization
  session and persists the route on the resulting credential, so no shared
  gateway proxy is written.
- A gateway without the POST capability answers with upgrade guidance instead of
  starting through another route. HTTP(S) proxies may omit the port, SOCKS5(H)
  proxies may not, and query parameters, paths beyond `/`, queries, fragments and
  the `direct`/`inherit` keywords are refused.
- Proxy input stays ephemeral. The required pre-start audit records the provider
  and not the proxy, and a proxied attempt that later fails records route intent
  only: Retry and the primary action then ask for the proxy again, while an
  explicit default-route action abandons it.
- Credential readback shows the stored route with its authentication masked, so
  the routing host stays visible and the password does not. The credential editor
  keeps an unchanged masked value out of unrelated field patches and refuses a
  submitted masked authentication before it reaches CPA.
- Selection moved into one bar directly above the rows, which appears with the
  first selected credential and disappears when the selection clears. It states
  the live count and any note about hidden pages, and groups page selection,
  **Select all filtered**, clear selection, the safe batch actions and delete.
- Select all filtered adds every eligible matching credential across pagination
  without changing the URL or the filters, keeps the selection that already
  exists, and leaves ineligible and runtime-only records out. It behaves the same
  across providers and filters, and on a phone the scope controls and batch
  actions become bounded two-column groups with that action on its own row.

## Dashboard model panels

- Clicking a model — a trend line, its legend entry, a ranked name or a ring
  slice — focuses that series as a highlight while every other line and slice
  stays painted for comparison. Hovering another line no longer replaces the
  reading, and clicking the same entry or the panel's background clears it.
- The trend tooltip keeps the complete ranking in legend order and lists quiet
  groups as zero. The ring's centre reports the focused group's tokens and its
  share of the full window; with nothing focused, the centre, the ring and the
  ranked list all read the full-window total, and a focused group with no tokens
  stays readable.
- The two panels share the console's chart legend, and each named entry carries
  the model's maker mark beside the rank's colour. The usage list shows the same
  mark, so a model is recognised before its name is read.
- The ranking is six rows and the card takes their height. The read folds every
  model outside the top five into one group, and a row pads 4px around a name
  pill that already holds its own hit area instead of the 7px a bare text line
  needed, which is what puts the sixth group back on the card without a
  scrollbar of its own.

## Provider editor

- A model entry's allowed thinking levels gain one select-all control beside the
  label. Setting it applies every known level and clearing it removes them, and
  both preserve levels the console does not know, so a value written by a newer
  gateway survives the edit. Only the entry being edited changes.

## Configuration

- The visual editor exposes CPA's five compression controls: downstream HTTP
  response compression and its minimum size for non-streaming responses, shared
  Codex request compression and its minimum request size, and Codex WebSocket
  compression. The omitted defaults (`true`, `1024`, `false`, `1024`, `true`) are
  shown without being written by unrelated edits, and an explicit `false`, zero
  or negative threshold survives a save.
- Each control states its scope where it is chosen: request compression covers
  only OAuth requests to the verified ChatGPT Codex backend and excludes API-key
  credentials, custom base URLs and SIWC; the response threshold does not apply
  to SSE; and the WebSocket switch moves compressed upstream writes and
  downstream negotiation while upstream negotiation stays enabled.
- These paths come from pinned CPA source rather than a live gateway, so the
  editor keeps its documented defaults while an older CPA that refuses a new path
  answers `config_rejected`. The revision, backup and audit boundaries are
  unchanged.
- The management-advertisement switch is retired from the visual editor, because
  updated CPA gateways accept its stored field and no longer advertise management
  endpoints. Discovery's enabled, service-name and authentication-required
  controls remain, and a stored `server.discovery.advertise-management` entry is
  still visible in the source editor and preserved by unrelated visual saves.

## Usage attribution

- Request rows, the request drawer and the provider facets resolve a provider by
  exact identity. A record carrying an `auth_index` resolves only when one
  current provider claims that credential; a deleted, rotated or ambiguously
  claimed credential stays unresolved rather than becoming a name guess. Without
  an index, only the exact configured id or CPA's full
  `openai-compatible-<upstream_name>` label identifies a provider.
- Display names, resource names, family labels and substring containment prove no
  ownership, and two providers claiming one identity stay ambiguous even when
  their display names match.
- An unresolved row keeps the resource name it has or CPA's raw provider key,
  shown as stored rather than rewritten for display, and a facet keeps the raw
  key. These joins read the current configuration and never rewrite stored usage.

## Model Square

- Credential provenance is bounded. One five-second budget is shared by the
  credential, configuration, static-definition and alias reads, and at most eight
  missing credential model lists are read with at most four in flight. Inline
  lists cost nothing and stay usable after the budget is spent.
- Each fetched list describes only its own credential, because accounts of one
  provider can differ in tier, prefix and routing. Exhausting the budget keeps
  the resolved routes and the complete advertised catalog, reports `routes` in
  `partial` and leaves unrepresented models without provenance. Successful alias
  rules travel with the snapshot, so a later timeout cannot erase known upstream
  fanout.
- Pricing discovery is unchanged: it still reads every model or fails closed, and
  this bounded snapshot is never persisted.

## Shell

- The desktop rail's expanded or collapsed choice is the `omc_sidebar_collapsed`
  server preference, expanded while no value exists, so the choice follows the
  operator into another browser. The header toggle and the collapsed brand's
  expansion wait for that read, an optimistic write rolls back when the server
  refuses it, and a malformed stored value is rejected rather than guessed.
  Phone navigation stays transient and never changes the desktop choice.

## Verification

- The affected plan follows ownership instead of whole layers: logic and rendered
  suites are discovered from parsed imports, Go packages from reverse
  dependencies, and browser scenarios from route and probe ownership. Ordinary
  pull requests run that plan, while `main`, nightly, manual and `full-ci` runs
  keep the complete catalog.
- Six duplicate fixture and source-text suites, CSS-source pins and
  presentation-only rendered cases are gone; their product claims stay with the
  Go wire certification, the typed-client contracts and the interaction and
  lifecycle suites. An equivalent change's fast plan fell from a 99.07-second
  median to 14.81 seconds on the same four-CPU host.
- Sustained cost growth is enforced rather than absorbed: three comparable local
  successes freeze a median, CI compares native job times against three-run
  baselines, and a failed run never becomes a baseline.
- Probe warm-up now renders the authenticated workspace it is warming instead of
  the sign-in screen and reports startup faults instead of swallowing them, so
  the Agent and Playground scenarios start from a mounted workspace.
- Vite keeps `lucide-react`'s dynamic icon map as native ESM in development,
  which stops thousands of icon chunks from becoming eager imports: an
  authenticated Agent mount requested 2,480 modules before and 815 after, and
  three guarded mounts after the change took 5.10, 4.99 and 4.61 seconds.
- Full verification keeps cancellation: `SIGTERM` and `SIGINT` still clean up the
  active checks, and no later group is admitted after cancellation.

## Upgrade notes

- Back up `.env` and the data directory or volume before upgrading; follow
  `docs/ops/sqlite-operations.md`.
- No migration runs. An install already on v0.3.10 keeps schema
  `048_usage_token_accounting.sql`, and an older install runs only the migrations
  its own version was missing. No stored usage row, price or credential is
  rewritten.
- The compression controls need a CPA build that knows their canonical paths. On
  an older gateway the editor still shows the documented defaults, and a save
  that changes a path the gateway does not accept answers `config_rejected`
  instead of partially writing. Verification of these five fields is against
  pinned source; writing them to a live gateway and the HTTP, SSE and WebSocket
  behaviour that follows remain unverified here.
- A session-scoped OAuth proxy needs CPA's `POST /oauth/auth-url` (upstream commit
  `27f3abfb`). An older gateway answers with upgrade guidance and starts nothing;
  the proxy-free Connect flow is unchanged.
- `server.discovery.advertise-management` disappears from the visual editor. A
  stored value stays in the file, remains visible in the source editor and is
  preserved by unrelated visual saves, so a gateway that still honours it is
  unaffected.
- Model Square responses can now report `routes` in `partial` while their model
  catalog stays complete. Pricing continues to discover every model or fail
  closed.
- The desktop rail's expansion is stored per deployment as a server preference.
  An install upgrading from an earlier release starts expanded because no value
  exists yet, and the phone drawer keeps its own transient state.
- Compose continues to default to `latest`. After publication, pin this release
  with `wiziscool/oh-my-cpa:v0.3.11` or `wiziscool/oh-my-cpa:0.3.11`.
- The CPA baseline is unchanged: CLIProxyAPI v8.0.0 or later, with the same v8
  Management API surface.
