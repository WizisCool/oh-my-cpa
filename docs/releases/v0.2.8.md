# Oh My CPA v0.2.8

## Credential window warmup

- **Codex and Claude window activation**: The OAuth management workspace adds Warmup settings and a Window warmup section on each credential's Quota tab. An explicitly confirmed tiny consuming request can start an idle subscription window for that exact credential and selected model; it does not replenish quota or spend reset credits.
- **Provider defaults and credential overrides**: Select a model, a reset mode (`off`, `weekly`, or `all`) and an optional daily start in the effective OMC Time Zone. Provider defaults apply to current and future inheriting credentials; a credential override replaces the complete policy. Automation starts off, and the default daily time is `06:00`.
- **Billing and activation safeguards**: Enabled or unknown paid fallback pauses both manual and automatic consuming requests. Automation also requires a manually confirmed activation observed for the exact credential and selected model. A completed HTTP request alone is not activation success: a fresh quota read and bounded follow-up checks report pending or uncertain outcomes when activation cannot be established.
- **Durable scheduling**: Policies, request receipts and cycle suppression survive restarts. Daily starts take priority over overlapping reset-driven activation, missed daily starts recover only within one hour, and unknown consuming outcomes are never replayed automatically. Only main five-hour and overall weekly windows participate.
- Warmup policy and execution are available through the Agent and MCP with the same confirmation and safety boundaries. The public demo displays the settings and observations but cannot save policies or consume quota.
- Credential editing retains unsaved drafts when another section saves, so warmup, label and model-rule changes can be completed independently.

## Compact phone surfaces

- **More content in the first screen**: The top bar names the page without a duplicate page heading. Dashboard statistics use two columns, list-row controls sit beside their content, and OAuth credential records are denser.
- **Three-line request records**: Phone request records group identity, tokens and timing into a compact layout. The request ID can be copied directly from the record, while the detail sheet retains the full fields.
- **Steady request-list scrolling**: The header folds through its explicit control rather than on the first scroll gesture, so the list stays under the finger. Phone filters use compact, wrapping controls without horizontal page overflow.
- **Opaque sheets and stable dismissal**: Full-width sheets remain opaque while sliding, and request details remain visible until the dismissal finishes. Touch targets retain their usable hit areas.

## Upgrade notes

- Back up the persistent SQLite database and preserve its master key before upgrading; follow `docs/ops/sqlite-operations.md`.
- Migration `041_credential_warmup.sql` adds durable warmup policy, state and run tables plus warmup observations on quota snapshots. Database rollback remains forward-only; do not run an older binary against the upgraded database.
- Warmup automation is off by default. Before enabling it, confirm the selected model and credential, establish disabled paid-fallback evidence, and complete an observed manual activation. Consuming requests use subscription quota and require operator consent; missing billing evidence leaves them paused.
- Existing quota auto-refresh settings and reset-redemption behavior are unchanged. Warmup does not require a new CPA endpoint or a Claude Code installation.
- Compose continues to default to `latest`. After publication, pin this release with `wiziscool/oh-my-cpa:v0.2.8` or `wiziscool/oh-my-cpa:0.2.8`. Docker images and native executable archives remain available through the existing release workflow.
