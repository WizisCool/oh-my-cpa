# Oh My CPA v0.3.19

This release makes a slow request visible before its number is read, and fixes the
provider and credential surfaces that had been quietly showing the wrong thing. Four
management defects are repaired: a management-key rotation that would have stranded OMC
on the old key, a provider brand mark that leaked another family's artwork, a plugin
login entry hidden because two plugins published the same provider name, and a provider
row whose name wrapped once a rename glyph took its width.

## Request duration

- Latency now reads on one continuous green-to-orange scale: green at an instant, orange
  at a minute, every wait in between on the way. It replaces the three bands, which could
  not tell two readings inside one band apart — which is what the colour was for.
- The ramp is the cache-rate badge's arithmetic, shared through one helper. Each reading
  keeps its own stops, and the two continuous scales cannot drift apart.
- A mix of two legible colours is not automatically legible — the mid-blend loses up to
  three tenths of a ratio point — so the duration stops are solved as a pair against the
  whole sweep they produce, on the page, surface, elevated, hover and selected fills. Every
  reading between the ends keeps its contrast, not just the ends.
- Time to first token loses its colour. It is request detail, not a verdict on the
  request, so it keeps the secondary ink its label uses; its interval tooltip and the tab
  stop that only existed to read that tooltip are gone with it.
- The request list, the detail drawer and the exported request-sheet image all read the
  same classification, so one record reads the same length everywhere.

## Structured upstream usage

- CPA's structured usage evidence is retained through the existing single-consumer
  ingestion path into a nullable, immutable request-level column, and is exposed in the
  single-request API, the Agent `requests_get` read and the request drawer. Request lists
  stay lightweight.
- Explicit zero and false are kept distinct from absent values, optional groups decode
  independently, and requested image settings are separated from what upstream observed.
  Map keys pass closed allowlists and every string, array and serialized document is
  bounded.
- Modality, TTL, tool, media and iteration observations stay separate from canonical token
  accounting. Upstream-reported monetary evidence is displayed separately from OMC's own
  immutable price-book estimate; historical totals and prices are unchanged.
- Malformed or shortened evidence is marked partial rather than repaired or dropped, and
  a legacy row remains unknown rather than zero.

## Credential renewal

- Renewal and recovery moved out of the Quota tab into a dedicated **Renewal** tab, so
  quota readings and credential lifecycle no longer share one surface.
- The panel leads with the renewal state and one sentence saying what it means, then a
  three-step evidence progression — runtime load, inference verification, automatic
  renewal — marked confirmed, unconfirmed or not yet observed, on a rail so it reads as
  one chain instead of repeated words.
- A credential is recovered through CPA's account-pinned OAuth flow: its name/index pair
  is resolved, target and proxy/verification intent survive retries, and CPA's matching
  target acknowledgement is required before a login URL is released.
- Inference verification is explicit, token-consuming, confirmed before it runs and
  admitted fail-closed through the audit. Only the verified outcome returns; credential
  bodies, OAuth codes, profiles and upstream error text stay out of ordinary responses
  and audit records.
- Exception states carry a warning mark and open the Renewal tab, while normal automatic
  renewal stays visually silent so a workspace scan still finds the exceptions. Missing
  evidence is kept distinct from confirmed false throughout.

## Provider identity

- Renaming a provider no longer requires opening the whole editor. Hovering a provider
  row shows a rename glyph, and the new `PUT /api/v1/management/providers/{id}/name`
  writes only OMC's own `provider_names` overlay — never CPA. A row moved by a concurrent
  delete answers `409 provider_stale_identity` instead of renaming its neighbour, and the
  write is audited fail-closed in all four locales.
- Provider brand marks resolve through one shared layer that keeps provider-instance
  identity, OAuth credential family and model-manufacturer identity apart, so an instance
  with saved artwork no longer borrows its protocol family's default. The same marks are
  used by the list, the routing board, the drawer and the exported image.
- A provider name keeps its single line in a width-constrained table: the column floor now
  includes the rename glyph's reserve instead of taking it out of the name's own width.
- Every OAuth provider a plugin declares appears as a login entry, with its owning plugin
  kept, so two plugins publishing the same provider name no longer hide one another.

## Kimi and Codex plans

- Kimi's optional coding profile is read through CPA after a successful usage read, on the
  same fixed host and with the same credential substitution. A name is accepted only from
  an identified profile, sanitized and bounded to 256 UTF-8 bytes without splitting
  characters.
- A failed, slow or malformed profile keeps the usable quota windows: each successful read
  receives a fresh plan and falls back to `Kimi Coding API` rather than the previous
  observation's name.
- `promax`, `pro-max` and `pro_max` are recognized as `Pro 500`. Raw plan identities and
  unknown-plan fallbacks are preserved, and historical snapshots keep the labels they were
  observed with.

## Configuration

- `client.claude.show-codex-commentary` is exposed in the visual configuration editor,
  defaulting to `false`, with copy in all four locales explaining that public Codex
  progress is mirrored into visible Claude text while private reasoning stays in thinking
  blocks.
- The management key is deployment-owned and read-only. A sparse write, a whole-document
  source save or a backup restore that would change `management.secret-key` is refused with
  `409 management_key_environment_owned` before any backup or CPA mutation, because OMC's
  encrypted instance credential, login verifier, remote MCP authentication and long-lived
  usage collector all hang off that key. Rotate it through the deployment environment and
  restart CPA and OMC together.
- Migration `056` repairs databases whose plugin development migrations took versions
  `053–055` before structured usage shipped as `053`: it checks the actual schema and
  restores the missing `structured_usage` column and its immutable trigger while retaining
  migration records, historical usage and cost data and pending inbox payloads.

## Upgrade notes

- Back up `.env` and the data directory or volume before upgrading; follow
  `docs/ops/sqlite-operations.md`.
- Schema version advances to 056 (`056_usage_structured_details_repair.sql`). The migration
  is forward-only and adds the structured-usage column where it is missing; existing
  usage, costs and pending inbox payloads are preserved, and an encrypted pre-migration
  backup is taken first.
- Request duration no longer carries a band tooltip. If you relied on reading the interval
  from that tooltip, the value itself is unchanged; only its colour became continuous and
  the interval wording was retired.
- No Compose or environment change is required. Compose continues to default to `latest`.
  After publication, pin this release with `wiziscool/oh-my-cpa:v0.3.19` or
  `wiziscool/oh-my-cpa:0.3.19`.
