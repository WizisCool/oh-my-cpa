# Oh My CPA v0.3.12

This release replaces Smooth scrolling with one Reduce motion preference the whole
console reads, and carries an existing scrolling choice forward through migration 049.
A phone scrolls the request list in the browser itself and opens its navigation as a
standard drawer; hints and menus answer an intentional gesture instead of the hover a
tap produces. The configuration workspace gains a card rail at wide widths, the
service-log panel shows its captured records again, and secondary copy is shorter in
all four locales.

## Motion

- Settings carries one Reduce motion control — On, Follow system, Off — in place of
  Smooth scrolling. On reduces motion whatever the machine asks for, Follow system is
  the default and tracks live `prefers-reduced-motion` changes, and Off allows full
  motion on a machine that asks for less. The choice is the `omc_reduced_motion` server
  preference, so it follows the operator into another browser, and an optimistic write
  rolls back when the server refuses it (ADR 0108).
- One decision covers the interface's transitions and keyframe loops through the
  `data-reduced-motion` root attribute the motion budget already checks, and the
  imperative consumers read the same live value: Dashboard and Insights charts, rolling
  numbers, routing travel and row entry, theme changes, progress bars, the Agent
  thread's stick-to-bottom scroll, and the console's programmatic scrolls — the request
  list's wheel glide, the provider reveal and the configuration card rail.
- A chart element a panel omits stays omitted, and axis-pointer motion keeps the
  defaults it inherits, so the preference removes motion without bringing back what the
  panel does not draw.
- Reduced motion omits the routing trip rather than shortening it: the diagram and its
  counts keep updating, and the shared system listener means a change needs no reload
  and does not replay trips that passed while the page was hidden.
- Migration `049_reduced_motion_preference.sql` stores an explicitly chosen scrolling
  behavior under the new key with that choice inverted (`on` → `off`, `off` → `on`,
  `system` unchanged), keeps an already stored reduced-motion choice, and removes
  `omc_scroll_smoothing`. An install with no explicit choice follows the system.
- `docs/design.md` and the architecture notes state the SPA's motion boundary, and what
  a standalone conversation HTML export does with it: a saved document follows the
  viewing machine's system preference, not the console's stored one.

## Phones

- Where a finger can scroll (`any-pointer: coarse`) the request list is an ordinary
  overflowing element, and the browser scrolls it on the compositor with its own
  tracking, momentum, tap-to-stop and edge behaviour. Rows away from the view are
  skipped with `content-visibility: auto`, and `overscroll-behavior: contain` keeps a
  drag at either end inside the list. Nothing changes for a mouse, including on a
  desktop narrowed to a phone's width (ADR 0109 supersedes ADR 0048's scripted driver,
  its coast and its touch fold).
- The header never folds by itself there: a scroll leaves the filters open, and the
  header's full-screen toggle folds and unfolds them. With a mouse the wheel's fold and
  the top bounce are unchanged.
- A stacked request record reads its cache hit rate beside the cost and its throughput
  on the quiet line, falling back to how long the call took when there is no output to
  measure. A rate of 0% keeps its pill, and the cached count stays in the rate's
  tooltip.
- An effort level spells `xHigh` in every badge, and in exported images, instead of
  capitalising the parameter's own prefix.
- An OAuth credential keeps its warm-up settings and quota refresh on one phone row,
  with the refresh stretching into the space the row has left.

## Pointer hints and the phone drawer

- The phone navigation is a standard antd Drawer with an accessible name and safe-area
  padding, and it closes when its brand navigates.
- Opening an overlay adds no browser-history entry, so Back always follows the page
  history the reader travelled. The overlay-history stack, its hook, its logic suite and
  its probe are gone; a browser-navigation probe asserts that Back leaves a page while a
  request drawer or the navigation drawer is open.
- One shared Tooltip opens after 450 ms of resting hover, on keyboard focus, or on a tap
  on plain text and marks. It never answers a tap on a control — that tap means "do it"
  — and stays down while the press's own menu or panel is open. After a hint closes, the
  next opens at once for half a second, so a reader moving along a row of tools is not
  made to wait on each one.
- Tab overflow menus, the OAuth credential menu and its caret, and the range calendar
  open on a press only, so the first tap on them is the tap that acts. The request
  list's delegated row popups answer the same gestures as the shared Tooltip.

## Configuration workspace

- From a 1600px viewport the settings column carries a card rail: one row per card of
  the current section — or per matched card under a search — stating how many settings
  the card holds and showing a warn dot when one of them is unsaved, which the section
  rail repeats on its section. The current card is the one under a judging line that
  travels with the scroll, and a row jumps to its card without a glide when motion is
  reduced. Below 1600px the rail is hidden and the workbench keeps its two columns.

## Service logs

- The service-log API finds the original redacted capture through transparent handler
  wrappers: `timezone.Handler` exposes `Unwrap` and `applog.BufferOf` follows it. The
  panel reads the capture buffer again instead of reporting an uncaptured logger;
  attributed and grouped loggers keep sharing that capture, loggers without a tee stay
  uncaptured, and redaction and sequence resumption are unchanged.
- `TestServiceLogsResumeFromTheLastSequence` now runs the production wrapper chain. It
  failed with `Capturing:false` before the fix and passes with redaction and resumption
  intact.

## Copy

- Hints, card subtitles, section descriptions and drawer introductions are rewritten in
  `zh`, `en`, `zh-Hant` and `ms` under the new captions section of
  `web/src/i18n/STYLE.md`: one calm sentence where the console used to hedge. A real
  hazard keeps its sentence — a credential's own model list overriding a provider's
  wildcard defaults, or clearing it to inherit them — while gateway version lectures,
  defensive disclaimers and explanations of the design's philosophy are gone.

## Upgrade notes

- Back up `.env` and the data directory or volume before upgrading; follow
  `docs/ops/sqlite-operations.md`.
- This release adds migration `049_reduced_motion_preference.sql`; v0.3.11 shipped
  `048_usage_token_accounting.sql`. It runs once, writes `omc_reduced_motion` from an
  explicitly chosen `omc_scroll_smoothing` with that choice inverted, keeps a
  reduced-motion choice that already exists, and deletes the old key. No usage row,
  price or credential is rewritten, and an install upgrading from an older release runs
  only the migrations its own version was missing. Migrations are forward-only.
- Smooth scrolling disappears from Settings, and the management preferences allowlist
  accepts `omc_reduced_motion` instead of `omc_scroll_smoothing`. A deployment that
  never changed the old switch follows the system, which is what the console's charts
  and transitions already did before the preference existed.
- The phone request list is no longer virtualized: a page of 500 records renders all of
  its rows once when it arrives, and rows away from the view cost no layout or paint. A
  phone shows fewer records at once while the filters stay open; the full-screen toggle
  buys the room back.
- Compose continues to default to `latest`. After publication, pin this release with
  `wiziscool/oh-my-cpa:v0.3.12` or `wiziscool/oh-my-cpa:0.3.12`.
- No API response or DTO changes, and the OMC Agent and MCP capabilities are unchanged.
- The CPA baseline is unchanged: CLIProxyAPI v8.0.0 or later, with the same v8
  Management API surface.
