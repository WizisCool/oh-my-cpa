# Oh My CPA v0.3.0

## Enable one-click updates

From this release on, Oh My CPA and CLIProxyAPI can be updated from the console instead of from a shell. A deployment that is already running needs one command, run once on the Docker host. The Compose file is not edited:

```bash
docker run --rm --pull always -u 0 -v /var/run/docker.sock:/var/run/docker.sock wiziscool/oh-my-cpa:latest updater install
```

- **What it does**: finds the running Oh My CPA container, adds an `oh-my-cpa-updater` container beside it, and upgrades Oh My CPA to this release in the same step. Settings, volumes, ports and networks are kept. CLIProxyAPI is not touched.
- **Afterwards**: **System Information** shows **Update now** beside a newer release of either product.
- **Images pinned to a version** (`wiziscool/oh-my-cpa:vX.Y.Z`, or `OMCPA_IMAGE` set to a tag or digest) are left as they are, by the command and by the console. Change the pin and redeploy to move them.
- **More than one Oh My CPA on the host**: add `--container <name>`.
- **To undo**: `docker rm -f oh-my-cpa-updater`.
- **What it costs**: the updater container mounts the Docker socket, which amounts to control of Docker on that host. It publishes no port, runs read-only with no capabilities, and accepts only two requests from the console: report status, and update Oh My CPA or CLIProxyAPI. Deployments that prefer not to run it keep updating with `docker compose pull && docker compose up -d`.

New installs get the updater from the Compose files and snippets in the install guide. `docs/install.md` ("Upgrading") covers every case.

## Updating from the console

- **One confirmed action**: the updater pulls the new image, replaces the container with its configuration intact, and waits for it to report healthy. A replacement that exits or stays unhealthy is removed and the previous container is started again.
- **Verified source for Oh My CPA**: each release publishes a signed manifest naming its exact image. The updater installs only that image, and never an older version. CLIProxyAPI is an upstream image this project cannot sign; its update pulls the tag the container already uses.
- **Progress through the restart**: updating Oh My CPA disconnects the console for a few seconds; the page keeps showing the update, then reloads on the new version. Updating CLIProxyAPI restarts the gateway and interrupts requests in flight.
- **Stated reasons**: when an update cannot be applied from the page (a pinned image, a gateway that is not a container on the same host, a build without the release key), the page says which.
- **Audit**: each update and its outcome are recorded in the audit trail.

## Upgrade notes

- Back up `.env` and the data directory or volume before upgrading; follow `docs/ops/sqlite-operations.md`. This release adds no SQL migration.
- Upgrading the old way (`docker compose pull && docker compose up -d`) still works and does not add the updater. System Information then shows the command above.
- The release Compose files (`compose.full.yml`, `compose.omc.yml`) and the install snippets now declare an `oh-my-cpa-updater` service. A deployment that added the updater with the command and later adopts one of these files must remove the installed container first (`docker rm -f oh-my-cpa-updater`), because the names collide.
- New settings: `OMCPA_UPDATER_ENABLED` (default `true`; `false` makes the console ignore an updater) and `OMCPA_UPDATER_URL`. Neither needs to be set.
- Native installations are unchanged and keep the manual upgrade in `docs/install.md`.
- Releases before v0.3.0 carry no signed manifest. This does not affect updating, because the target is always the newest release.
- Compose continues to default to `latest`. After publication, pin this release with `wiziscool/oh-my-cpa:v0.3.0` or `wiziscool/oh-my-cpa:0.3.0`; a pinned deployment is not updated from the console.
