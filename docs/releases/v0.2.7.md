# Oh My CPA v0.2.7

## Automatic quota refresh

- **Readings refresh in the background**: A one-minute loop re-reads credentials that are due, so an exhausted credential stops reading as exhausted once its window has reset. Reads take the same path as a manual refresh; a failed or stale read never replaces the last good one.
- **Refresh after a quota resets**: About a minute after a window the stored reading reported has reset, the credential is read once. A failed read is retried every ten minutes during the hour after the reset and then left alone.
- **Scheduled quota refresh**: Every credential whose reading is older than the interval is read, including one nobody has read. The interval defaults to six hours and is adjustable from 5 minutes to 24 hours, or off.
- Both triggers are on by default and are edited on OMC Settings → Quota. They are stored with the deployment as the `omc_quota_auto_refresh` preference, and the Agent and MCP reach them through `quota_auto_refresh_get` and `quota_auto_refresh_set`.
- A round reads at most 16 credentials, 4 at a time, reset-driven reads first and then the oldest readings. Disabled credentials, providers without a probe, an `auth_index` two credentials claim, and Meta credentials are never read automatically. Demo mode does not start the loop.
- The OAuth management workspace re-reads the stored overview every minute, as the dashboard's Credential Quota panel does, so new readings appear on open pages.

## Update indicator

- **Update available**: The System Information navigation entry carries a marker while Oh My CPA or CLIProxyAPI has a newer published release. It shows in the expanded rail, the collapsed rail and the phone navigation sheet, and the entry's accessible name reports it.
- **Ignore this version**: A product row with an available update offers a toggle that dismisses that one version. The dismissal is stored with the deployment as the `update_dismissals` preference, so it holds across browsers and restarts; a later release is marked again.
- `GET /management/system/updates` returns both products' stored version answers without reading the release feed. An open console re-reads it hourly. The release sweep, its interval and the request floor are unchanged.

## Console font and charts

- **Complete console font**: Sarasa Mono SC ships whole, split into `unicode-range` shards, so Traditional Chinese text and text that arrives at run time (Agent and Playground answers, model names, typed labels) no longer fall back to a system font. Startup still waits for one font file per weight; a browser downloads a further shard only when a page draws one of its characters.
- A conversation export embeds only the shards its text draws.
- Charts refit when their container changes size, not only on a window resize. The dashboard's model ring stays centred on its readout when the font arrives after the first paint.
- The embedded distribution grows from about 13.9 MiB to about 25.8 MiB, which the Docker image and native archives carry. Fonts fetched on first load grow from about 210 KiB to about 460 KiB.

## Upgrade notes

- Back up the persistent SQLite database and preserve its master key before upgrading; follow `docs/ops/sqlite-operations.md`.
- This release adds no database migration. The quota refresh policy and update dismissals are new keys in the existing preference table.
- Automatic quota refresh starts on upgrade. In the first minutes, every enabled credential whose reading is older than six hours, or that nobody has read, is read against its provider, at most 16 per minute. After that each credential is read about every six hours and after each reset. Turning both triggers off on OMC Settings → Quota restores operator-only reads.
- Compose continues to default to `latest`. After publication, pin this release with `wiziscool/oh-my-cpa:v0.2.7` or `wiziscool/oh-my-cpa:0.2.7`.
