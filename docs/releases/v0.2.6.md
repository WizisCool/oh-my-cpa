# Oh My CPA v0.2.6

## Provider connectivity and configuration

- **Test serving ability**: Provider editor Test controls send a fixed minimal inference request through the selected provider family instead of only fetching its model directory. Probes have a 30-second timeout, require a resolvable model, and support Vertex's Interactions routing option. They make an external provider call and are unavailable in demo mode.
- **Stored secret boundaries**: A stored key is used only at its configured endpoint. Changing the base URL or choosing a proxy requires the key to be re-entered; stored headers are not borrowed across endpoints. Every attempt is audited before sending, response bodies are discarded, and failure details are bounded and redacted.
- **TURN ICE servers**: The configuration editor supports ICE server URLs and explicit keep, replace and clear states for TURN secrets. Reordering servers or changing their identity requires secret re-entry rather than restoring a secret to a different server.
- Shared provider settings use CPA's canonical `upstream.*` paths while retaining supported historical aliases. Invalid model-pull proxy URLs are rejected instead of falling back to an environment proxy.

## Quota and request records

- Plugin-advertised credentials can refresh quotas through their matching plugin; one credential-aware capability resolver keeps refresh, overview and detail behavior consistent. Built-in readers take precedence.
- Eligible Claude reset grants survive snapshot persistence and remain visible after refresh and reload. They are display-only; this release does not claim grants.
- Codex credit redemption requires an explicit successful redemption status. A failure to clear gateway cooldown is reported separately from redemption success.
- xAI products remain visible when their usage share cannot be read, with unknown usage rather than a fabricated value.
- Request details show CPA's `access_provider` and `is_native_key` caller-authentication facts. They describe how the caller authenticated, not which upstream credential served the request. Historical records and older gateways retain an unknown state when those facts are absent.

## Console and portability

- The header GitHub link displays the project's star count after a successful server-side read. Reads are limited to once an hour and respect the update-check switches; a refresh failure retains the last successful count.
- The side rail no longer repeats a status footer. Default-button hover ink uses the accent, and Codex/xHigh display casing is consistent. Design documentation and affected README screenshots match the adopted console.
- Read-only SQLite queries preserve Windows drive letters in escaped absolute file URI paths while retaining read-only and connection limits.
- Native archive creation treats drive-letter paths as local GNU tar paths, preserving deterministic ordering, timestamps and ownership. Drive-letter regressions run portably; local validation was performed on Linux rather than a Windows host.

## Upgrade notes

- Back up the persistent SQLite database and preserve its master key before upgrading; follow `docs/ops/sqlite-operations.md`.
- Migration 039 adds caller-authentication fields to usage events. Migration 040 adds Claude reset-grant storage to quota snapshots. Migrations run automatically at startup; older records are not backfilled with authentication facts that were never captured.
- Existing retention settings and defaults are unchanged. Preserve operator configuration and TURN credentials when upgrading; secrets are not returned by safe configuration reads.
- Provider probes can use billable upstream inference and must be invoked deliberately. General browser access to CPA's arbitrary `api-call` remains closed.
- Compose continues to default to `latest`. After publication, pin this release with `wiziscool/oh-my-cpa:v0.2.6` or `wiziscool/oh-my-cpa:0.2.6`.
