# Oh My CPA v0.3.14

This release adds a display currency for what the console reads, replaces the two
outermost themes, and lets a Codex credential warm its window with credits available.

## Display currency

- OMC Settings → Data display → Display currency offers eleven currencies: USD
  (default), CNY, EUR, JPY, GBP, HKD, SGD, MYR, KRW, AUD and CAD. The preference is
  stored on the server, so it follows the deployment across browsers.
- Dashboard, Request Records and their cost details, the request image export and
  Insights print in the chosen currency, each amount carrying one fixed symbol against
  its number (`$`, `¥`, `€`, `£`, `HK$`, `S$`, `RM`, `₩`, `A$`, `C$`).
- Accounting stays in USD. Cost & Usage, price editing and price-version history,
  request filters and JSON exports keep their stored USD values: a new rate changes what
  a window reads as, never what a request cost.
- Reference rates come from Frankfurter v2's USD-base snapshot and persist in SQLite
  (`exchange_rate_cache`, migration 050), so reads and conversions need no internet
  access. The server downloads once a day; the refresh glyph beside the picker updates
  the rates on demand, and a non-USD choice states its rate for 1 USD with that quote's
  observation date.
- A currency with no cached rate reads as unavailable rather than being relabelled as
  USD, and a snapshot missing any of the eleven quotes is refused whole instead of
  publishing mixed old and new rates.
- The download names a fixed endpoint, takes no source URL and sends no CPA credentials.
  One refresh runs at a time, and demo mode serves synthetic rates and refuses a refresh.

## Themes

- Pewter and Fog replace Midnight and Porcelain as the registry's outer dark and light
  palettes. Each builds its neutrals — page, cards, rules and the text ladder — on one
  hue at low chroma, so the layers read as one material: Pewter is a dimmed steel slate
  with an iris accent, Fog a cool mist with cobalt.
- Palette ids, the retired-id mapping and the stored preference are unchanged, so a
  saved selection and an authored palette based on either one carry over.

## Credential window warmup

- Codex manual and automatic warmup now proceeds regardless of credit status, including
  an unknown balance, so a credential that has credits available is no longer paused.
  Quota freshness, model selection, idle-window evidence and the duplicate-request guards
  are unchanged, and an unknown outcome is still not replayed automatically.
- Codex warmup may incur charges. The warmup status card, the settings and manual-run
  confirmations, and the agent capability descriptions state that.
- Claude is unchanged: it still requires paid fallback to be affirmatively disabled, and
  an unknown or enabled fallback pauses its consuming requests.

## Upgrade notes

- Migration 050 creates the rate cache on the first start after the upgrade. The
  mandatory pre-migration backup and its restore check run as they do in v0.3.13; no
  manual step is needed and existing data is untouched.
- A deployment that cannot reach `api.frankfurter.dev` keeps working: reads use the
  cached rates, and non-USD amounts stay unavailable until an update succeeds. USD is the
  default and needs no rate.
