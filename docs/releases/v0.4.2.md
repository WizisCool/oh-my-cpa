# Oh My CPA v0.4.2

Oh My CPA v0.4.2 hardens automatic container updates and rollbacks during slow SQLite migrations, adds a complete Swagger 2.0 OpenAPI specification with self-hosted API documentation and unified site staging, and improves live request-list and routing-map readability.

## Automatic updater & rollback resilience

- **Extended image startup grace window and configurable health timeout.** Raised the Docker `HEALTHCHECK --start-period` from `5s` to `180s` (`--interval=10s --timeout=5s --retries=3`) so slow pre-migration backups and table-rebuilding SQLite migrations stay `starting` instead of failing early as `unhealthy`, while process exits still fail immediately. Raised the updater's default `HealthTimeout` from `3m` to `5m` and added `OMCPA_UPDATER_HEALTH_TIMEOUT` (validated on startup and forwarded by `updater install`), allowing explicit deadlines to wait through transient `unhealthy` states while the replacement remains running without restarts.
- **Clean rollback ordering and stale-backup cleanup.** Added `stopAndRemoveContainer` and `Restarting` state detection so failed replacements are stopped cleanly to release network sandboxes and published ports before removal, retried transient container-removal and port-allocation conflicts without swallowing deletion errors, and reconciled stopped `*-omc-previous` backups automatically when the running target is `healthy` and requires no updater self-handover.

## OpenAPI specification & public site

- **Swagger 2.0 OpenAPI export and parity gates.** Annotated all `/api` routes in `internal/api/` with explicit safe DTOs and generated `docs/openapi/swagger.json` using pinned `swag` (`pnpm openapi:generate` / `pnpm check:openapi`), enforced by `TestOpenAPIRouteCoverage` and `TestOpenAPISpecFreshness`.
- **Self-hosted API documentation and unified site staging (`deploy/site/`).** Added `pnpm build:api-docs` (self-hosted Scalar UI over `docs/openapi/swagger.json`) and `pnpm build:site` to compose the landing page, `/api-docs/`, and `/demo/` together, and added a Demo-only API docs link to the console header across all four locales.

## Usage events, live routing & documentation

- **Calm live request pagination.** Refetched `usage-events` in place when live SSE updates arrive instead of rotating the React Query key, eliminating repeated `Updating` footer flicker while preserving loading states on operator filter and page changes.
- **Slimmer live routing map.** Reduced `MAX_DRAWN_MODELS` and `MAX_DRAWN_TARGETS` from `7` to `4` (and trimmed the demo traffic simulator to 3 models and 4 credentials) so dense live routing views remain readable.
- **README screenshots.** Refreshed the English and Chinese README console screenshots.

## Upgrade notes

- Back up `.env` and your SQLite database or volume before upgrading; refer to `docs/ops/sqlite-operations.md`.
- No new database migrations are introduced in v0.4.2.
- Operators running large SQLite migrations during automatic container updates can configure `OMCPA_UPDATER_HEALTH_TIMEOUT` (default `5m`) on the updater; images built from v0.4.2 onward also carry the `180s` health-check start period for future upgrades.
- Container images are available on Docker Hub as `wiziscool/oh-my-cpa:v0.4.2` and `wiziscool/oh-my-cpa:0.4.2`.
