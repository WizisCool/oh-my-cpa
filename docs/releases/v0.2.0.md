# Oh My CPA v0.2.0

## Agent

- An answer can carry an interface. The model draws with one display tool,
  `render_ui`, and the console shows the result where the call sits in the
  answer, inside a script-only sandbox that loads nothing from the network. A
  generated interface is composed from the console's own kit - stats, tables,
  charts, diagrams, tabs and controls - reads the rows an earlier capability
  result froze, and is drawn while it is still being written.
- `/` opens the page's commands and `@` completes a model, a client key alias
  or a capability name; Up recalls sent messages. `/ui` and `/text` set how the
  next answer is presented.
- A message can carry up to four images and up to four text files. Images are
  stored encrypted beside the conversation for as long as their turn is part of
  it.
- The newest turn can be retried or edited, the model can offer follow-up
  questions, and a call's details open under the call. A ring under the composer
  states how much of the model's context window the conversation occupies.
- Runs and sessions have no token, round or duration ceiling of the console's
  own. A long conversation grows the database and the cost of each request; use
  New conversation to release it.

## Inference endpoints

- The Agent and the Playground send a conversation to CPA's Chat Completions,
  Responses or Messages endpoint, chosen on a chip in the composer and
  remembered. Turns, diagnostics, usage and recovery read the same whichever
  endpoint answered.
- Reasoning effort is written in each endpoint's own form. On Messages it is
  sent as adaptive thinking with an output effort, and `none` turns thinking
  off; a model or CPA build that predates that form rejects it, and the
  Playground's custom request body can state another.
- On Responses and Messages the Playground's custom request body may not
  replace the conversation (`input`, `messages`). Every other field still
  overrides.
- A Messages request always states a token limit: 4096 from the Playground when
  none is set, 16384 from the Agent.

## Playground

- The key, model and reasoning effort are chosen on chips in the composer, as on
  the Agent page. The head's two selects and its refresh action are removed;
  refresh is in the model chip's list.
- Reasoning effort is one of the named levels. A provider-specific level is set
  through the custom request body, and the panel's Reset no longer clears effort.
- A model chosen just before a reload is kept, and the message box takes focus
  before a model is chosen.

## External agents

- The capability registry is served over MCP Streamable HTTP at
  `<console URL>/api/mcp`, authenticated by the CPA management key as a bearer
  token, beside the existing `oh-my-cpa mcp` stdio bridge. Nothing needs to be
  installed where the agent runs.
- An operation that needs approval returns a link to a consent screen in the
  console, where the signed-in operator allows or denies it. An external agent
  can prepare an operation and wait for the decision; it cannot approve one.
- The Agent page's Connect guide gives the deployment's address and
  ready-to-copy configuration for common MCP clients.

## Conversation export

- The Agent and the Playground export a conversation as a self-contained HTML
  page, a PNG image or JSON. These replace the Markdown report. An export is
  built from what the page displays: key fingerprints, tokens and run
  identifiers are left out, and the page allows no network access.

## Quota

- Grok subscription credentials show their usage window, Kimi plans without a
  weekly limit show their usage, and a Codex free plan's monthly limit is no
  longer labelled as a five-hour window.
- A read that came back with no usage published is shown as such, instead of
  reading like a credential that was never checked.

## Phones

- The Agent's first screen, command lists, approval card and composer are laid
  out for a phone, and the page actions step aside while the keyboard is up.
- Tables keep each figure on one line and scroll sideways; charts are drawn at
  the width of the screen, so their axis text stays readable.
- An icon action's label no longer appears over a control that was not touched.

## Reliability and security

- Usage payloads already received are kept when a subscription closes or the
  process stops, and the ingest pipeline finishes before the database closes.
- The backup taken before a migration includes rows that were still in the
  write-ahead log.
- The CPA management client does not follow redirects, upstream status and
  error text is redacted before it reaches an ordinary response, and an
  auth-file field write answers `409` when the file changed after it was shown.
- Collector status reports `failing` after a failed capture until the next
  successful one, and an operation still running reads as `executing` rather
  than `uncertain`.

## Upgrade notes

- Back up the persistent SQLite database and preserve its master key before
  upgrading; follow `docs/ops/sqlite-operations.md`. This release adds one
  migration, `036_agent_image_documents`, which rebuilds the `agent_documents`
  table to hold Agent images. It runs automatically on first start and is not
  reversible by downgrading.
- A reverse proxy that sets its own Content-Security-Policy must keep
  `frame-src 'self' blob:`; the Agent's generated interfaces are drawn in
  sandboxed frames.
- The remote MCP endpoint accepts the CPA management key, which is
  administrator-equivalent. Serve the console over HTTPS before connecting an
  agent from another machine.
- The stored Playground session keeps its key, model and reasoning effort. A
  free-text effort outside the named levels stays selected until it is changed.
- Compose continues to default to `latest`. To pin this release after publication,
  use `wiziscool/oh-my-cpa:v0.2.0` or `wiziscool/oh-my-cpa:0.2.0`.
