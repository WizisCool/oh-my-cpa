# Oh My CPA v0.3.1

This patch follows CLIProxyAPI v8.0.31 and CPAMC v1.26.5: the settings CPA added after
v8.0.16 are editable, a configuration write is refused instead of overwriting a save made
outside Oh My CPA, quota readings follow what the vendors and CPA now report, and the
plugin host carries the console session on same-origin plugin fetches.

## Gateway compatibility

- **Baseline**: CPA **v8.0.31** and CPAMC **v1.26.5**.
- **Configuration writes carry CPA's entity tag.** Every write sends `If-Match` with the
  tag of the file Oh My CPA read and backed up immediately before it, and each later
  request of a change set names the tag CPA reported for the previous save. A writer
  outside Oh My CPA that saves in between now makes CPA answer `412`, which the console
  reports as `config_conflict` (nothing written) or `config_partially_applied` (an earlier
  request of the set had already landed). Gateways that report no tag keep writing
  unconditionally, as before. The backup is always the version that was replaced.
- **A request CPA refuses as too large** (`server.max-request-body-bytes`, which also caps
  management routes) is reported as `cpa_request_too_large` with the setting to raise,
  instead of a generic upstream failure.
- **New settings are editable**: the request body limit, the session-affinity rebind
  condition (`any` or `quota`), the TLS handshake timeout, heartbeats before the first
  token, Claude tool search with its four header overrides (strip and append
  `Anthropic-Beta`, diagnostics injection, `x-client-request-id` handling), and the Sign in
  with ChatGPT identifier. The Claude provider editor gains a per-key **Native tool search**
  switch, stored under CPA's wire name. A gateway older than the release that introduced a
  setting refuses a write to it; an untouched setting is never written.
- **`quota-exceeded.switch-project` and `switch-preview-model` left the settings page.**
  CPA still writes and keeps both keys, but as of v8.0.31 nothing in its request path reads
  them. The source editor keeps them.
- **Vertex probing** follows CPA's own URL builder: a base that already ends in a version
  segment such as `/v1beta1` gains no `/v1`, and a base naming a `publishers` resource
  gains only `/{model}:generateContent`.

## Quota readings

- **Claude credit pools read as plan balances.** A dollar-denominated `iguana_necktie`
  reading is the cloud session credit pool rather than the legacy Fable window, so a spent
  pool no longer marks the credential exhausted or gates Fable warmup. Other complete
  dollar windows become balances too, and extra usage is reported when it is off, with its
  currency, reason and spend-limit flags.
- **Balances survive a failed profile read**: balances and extra usage ride on a plan of
  unknown type instead of being dropped.
- **xAI** `product_usage` is read as a breakdown of the shared credit usage rather than
  per-product limits, and a zero pay-as-you-go cap reads as off. A cap that cannot be read
  is no longer reported as off.
- **Antigravity** bucket names drop the `Remaining` suffix and fall back to the window
  field when a name is unclassifiable; a window Meta cannot classify is named by its length.
- **Client identities** follow CPA v8.0.31: Grok CLI 1.0.46 and Antigravity Hub 2.23.0,
  because both vendors now refuse the older builds Oh My CPA previously impersonated.
  Plugin quota reads use CPA's reported `quota_plugin_id`, falling back to name matching
  only on gateways that do not report it.

## Plugins

- **Declared defaults**: CPA v8.0.27 lists each plugin setting's default, and the settings
  drawer names it in an empty control. An unset boolean shows the declared state.
- **Plugin pages keep their session and their provider.** The host adapts same-origin
  native API and resource fetches to carry the Oh My CPA session, including pages that set
  `credentials: 'omit'`; explicit credentials and the existing security gates are
  unchanged. A plugin script that identifies its provider through
  `location.pathname` now receives the CPA-native resource path, while the frame itself
  stays under the configured console base path.
- **Sidebar settings**: a plugin page's logo keeps its 16px glyph size in the entries panel
  as it does on the rail.

## Upgrade notes

- Back up `.env` and the data directory or volume before upgrading; follow
  `docs/ops/sqlite-operations.md`. **This release adds no SQL migration**: the schema is
  the one v0.3.0 migrated to, still ending at `042_fonts.sql`.
- No new settings and no environment variables. An update from v0.3.0 needs no
  configuration change.
- Configuration conflict protection is only available against CPA v8.0.31 or later. On an
  older gateway a writer outside Oh My CPA that saves the same family between the read and
  the write is still overwritten, as before this release.
- Raising Oh My CPA ahead of its gateway is safe: settings the gateway does not know are
  never written until the gateway accepts them, and the editors say when CPA refused.
- Compose continues to default to `latest`. After publication, pin this release with
  `wiziscool/oh-my-cpa:v0.3.1` or `wiziscool/oh-my-cpa:0.3.1`.
