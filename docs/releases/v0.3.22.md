# Oh My CPA v0.3.22

This release is mostly about the dashboard and the surfaces around it: the dashboard and
the routing board rearrange by dragging, widgets resize from their edges, quota windows
state what is left of them, and every provider is named the same way on every page. Two
pieces of groundwork sit beside them: reference prices for models OpenRouter cannot
price, and CPA's persistent KV settings exposed in the configuration editor. The bundle
gets lighter and sharper — hinted Sarasa Latin with CJK glyphs from Google Fonts — and a
release whose bundled model snapshot is older than a month is refused.

## Drag and resize

- OAuth credentials, AI providers and the sidebar reorder by drag with one pattern
  (`RowReorder` on dnd-kit). On wide screens the handle hides along the row's leading
  edge; on phones it sits inline and on touch screens without hover it stays visible.
  Rows sort live without dimming, a reflow can never trigger a swap on its own, and the
  drop keeps the new order on screen until the stored preference arrives. A focused
  handle moves its row with the arrow keys.
- Display orders are presentation only. `provider_order` and `routing_card_order` are
  positional overlays that the server re-keys when a provider is deleted or moves
  family, and the preferences endpoint now refuses a positional overlay that is not an
  object of strings — a stored value of the wrong shape would have made every later
  provider save, move and delete fail.
- Dashboard widgets drag and resize like the lists: the same drag library, a travel
  threshold, no swap from reflow alone, the lifted widget shown whole and no fly-in on
  drop. Widgets resize from an edge or the corner, snap to grid columns and rows, and
  never get shorter than their content. Keyboard resizes are announced from a live
  region. Provider and credential-quota widgets sort by the same shared layer, backed by
  the grouped `omc_dashboard_order` preference, so a further list needs no preference
  plumbing of its own. KPI figures size to the tile's width and share one baseline.
- A number field under the pointer steps with the wheel, without a click first, using
  the field's own step and bounds (`NumberInput`). A field locked by a disabled form
  leaves the wheel to the page.
- The routing board lets cards be dragged within a tier. Cards glide into place whatever
  their width, and none flies in on drop. Tiers fold in and out as they are created and
  emptied, and the new-tier link keeps its height while a card crosses it. Shares and
  share bars appear only once a model is selected. Zero-weight cards dim instead of
  widening, and the failover settings no longer wrap.

## Dashboard layout and colours

- Paired cards end on one line. Board heights fitted to content used to round up to the
  next 40px step, leaving empty space under the shorter card of a pair; they now round
  down and the tracks grow by the remainder, so a card is exactly as tall as its content
  and its neighbour ends on the same line. Model trend/usage take 9 rows by default,
  token activity/credential quota take 6. The trend is the elastic side of its pair and
  may shrink to 190px, so the ranked usage list sets the pair's height. A height drag
  counts from the widget's stored rows rather than its box, which a content-fitted card
  makes taller than its rows; a small nudge no longer adds a row. The overflow that ran
  the trend's time axis about 56px past the card's bottom is fixed.
- The model trend and usage ring use the standard `series` palette (blue, emerald,
  violet, rose, amber, cyan) instead of the separate warm/cool `model` palette, which is
  removed. The token-activity heatmap fits its cells to the widget's height as well as
  its width, so its last weekday row and legend line up with the credential-quota list
  beside it and a hovered cell's outline is not clipped.
- The live routing map is redrawn in the sign-in page's wire style: tiles facing a
  gateway tile, hairline neutral lanes, and each request a short stroke of light that
  goes out in the map's light and comes back green for an answer or red for a refusal.
  Both columns hug the gateway so the logo stays centred and the two sides weigh the
  same. Rows show only a model and its request count, a provider and its credential, and
  a cooldown or failures when there are any.
- Redundant page refresh buttons are removed where the shell header's **Refresh all**
  already re-reads the page's queries: Dashboard (and its duplicate load-failure Retry),
  Insights, AI Providers, API Keys, Plugins, Pricing, Routing, System and Audit. Buttons
  that do work a re-read cannot stay — usage records, Model Square, credential and OAuth
  quota refresh, exchange-rate refresh and the log tail.

## Quota capacity estimates

- A window's remaining capacity now gives a figure once the window has used any quota
  through the gateway, and states what is left of the window as well as its size. The
  old estimate withheld itself below five used points, after a gap in history, on
  approximate reset instants or after a mid-cycle reset.
- Consumption between two readings is divided by the used-share change between them, so
  usage recorded before the gateway's first reading no longer skews the estimate and a
  reset no longer blocks it. A small sample (under 5 points) is blended with the latest
  earlier estimate in proportion to its size, so a window that has just reset keeps a
  size; a plan change starts a new calibration. Trimming keeps the first and last
  readings of each window's latest three cycles beside the recent tail, so frequent
  refreshes no longer evict the readings a change is measured from. Reset instants
  within a second count as one cycle, as Codex's derived instants drift between
  refreshes.
- A live reading adds `remaining_tokens` and `remaining_cost_nanos` — the only
  additions to the response. A dollar figure still needs 95% of sampled requests priced;
  otherwise the figures are tokens. The drawer states *Est. remaining* in bold and
  *Est. capacity* under each bar; the list row shows what is left and its tooltip names
  both figures.

## Provider names and artwork

- `providerDisplayName` is the one name every provider surface gives a provider key:
  the title a plugin publishes for a provider it registers, then the brand table, then
  the key as recorded. The dashboard and the OAuth page both read it, so a brand is no
  longer spelled from its raw key on one page (`Deepseek`) and by its own name on the
  other (`DeepSeek`). Titles are keyed by the canonical key, so an alias reads the same
  as the section the OAuth page files it under.
- Registered plugin and OAuth artwork loads in the browser without a server-egress
  dependency, and credential branding resolves through declared quota-provider
  identities. Remote catalog artwork and identity fallbacks are restricted to installed
  plugins from a matched source; other catalog entries use inline artwork or
  placeholders.
- Plugins that register a management page keep an explicit direct sign-in action beside
  the separate page action. Start sign-in shows device-code or redirect controls only
  after a usable authorization URL and session identity are returned; plugin-page
  navigation is disabled while any authorization is starting or waiting, without
  blocking concurrent provider sign-ins. Incomplete starts that already hold a token can
  be cancelled, and a retryable cancellation is offered when that fails.

## Pricing

- The bundled models.dev snapshot now carries each provider's listed base rates per
  canonical model, grouped where providers agree. The price editor lists these reference
  rates for a model without an automatic price; adopting one fills an ordinary custom
  price, so OpenRouter stays the only automatic source and price versions stay
  append-only. Zero-rate listings and long-context/audio surcharges are left out.
  `pricing_get` describes the reference rates to the Agent.
- The installed-plugins list checks the registry for a newer version and applies it in
  place through the existing install flow, extracted into a shared `PluginInstallModal`.
- The bundled snapshot itself moved from 2026-10-05 to 2026-11-05, from 441 to 608
  canonical models (10,326 exact aliases).

## Configuration

- CPA's persistent local KV storage gets visual controls in the configuration editor,
  and Claude's memory-only date-pin retention is clarified in all four locales. Omitted
  defaults and existing retention values pass through the existing revision-checked
  configuration flow; concurrent siblings survive a newly created draft map rebasing
  onto a newer configuration.

## Fonts

- The default typeface stays Sarasa Mono SC, but the bundle now carries only Sarasa's
  own side of it, with TrueType hinting kept. Previously the hinting was stripped, which
  made small text look soft on Windows; Regular, SemiBold and Bold now ship and most
  emphasis set at 600 renders as SemiBold instead of Bold.
- Sarasa's CJK glyphs are Source Han Sans, which Google Fonts serves as Noto Sans SC.
  The console fetches Google's stylesheet and registers its faces under a private
  family, each narrowed to the ideograph and Hangul ranges the bundle leaves out, so
  Noto's Latin and monochrome emoji never draw over Sarasa or colour emoji. The
  ideographs the console's own copy uses stay bundled, so its labels draw in Sarasa from
  the first frame; without Google, the platform's CJK font draws the rest. Conversation
  exports embed the Noto slices they need, with an 8-second timeout.
- Font shards drop from 12.5 MiB to 3.2 MiB and the built SPA from about 31.5 MiB to
  21.2 MiB. The CSP allows the two Google Fonts origins, and the acceptance browser
  guard blocks them, so every check exercises the fallback. An asset may come from a
  public CDN when it is chosen for it; a deployment that cannot reach the CDN still
  renders the console with the asset's local fallback.

## Reliability

- Migration backup encryption and verification stream instead of building the whole
  encrypted copy in memory, interrupted attempts are cleaned before a retry, retained
  disk usage is bounded, and backup and migration stages are logged. Legacy backup reads
  are preserved.
- Model Square's reference specifications come from a models.dev snapshot compiled into
  the binary, and nothing had advanced it after the feature landed. Release preparation
  now refuses a release whose snapshot is more than 30 days older than the tagged
  commit, measured against the commit date rather than the clock, so rerunning the same
  tag gives the same verdict. This adds no runtime network access. The Model Square
  summary and detail note call the date the **bundled** models.dev snapshot, so it does
  not read as the time of the last CPA catalog refresh; **Refresh model catalogs** keeps
  its scope and still refreshes only CPA.

## Upgrade notes

- Back up `.env` and the data directory or volume before upgrading; follow
  `docs/ops/sqlite-operations.md`.
- No schema migration: the database stays at version 057.
- Existing stored layouts, orders and preferences keep their saved values; new layout
  fields only add what a drag or resize writes. The preferences endpoint now refuses a
  `provider_order` or `routing_card_order` that is not an object of strings — a value of
  the wrong shape stored before this release would have made every later provider save,
  move and delete fail, so check such a value if provider writes ever failed.
- The dashboard's model palette changes; token trend and usage ring follow the standard
  series palette. Saved layouts are unchanged.
- Console CJK text beyond the bundled subset loads from Google Fonts. A deployment
  whose network cannot reach Google Fonts still renders the console with the platform's
  CJK font; the CSP change is additive.
- A live quota reading may add `remaining_tokens` and `remaining_cost_nanos` to the
  response; nothing existing is removed or renamed.
- No environment variable or Compose change is required. Compose continues to default
  to `latest`. After publication, pin this release with `wiziscool/oh-my-cpa:v0.3.22` or
  `wiziscool/oh-my-cpa:0.3.22`.
