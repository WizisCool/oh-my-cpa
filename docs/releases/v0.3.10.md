# Oh My CPA v0.3.10

This release adds the Insights analytics workspace, makes usage accounting,
pricing and TPS follow the evidence a request actually carries, reorganizes the
OAuth workspace around provider sections, and moves Agent answers onto OpenUI.
It also adds per-group sidebar ordering and paces Claude quota reads so they stop
colliding.

## Insights

- `/insights` is a new analytics workspace. One cube-backed snapshot drives
  metric tiles, trend, rankings, key composition and detail, flow and the
  weekday/hour rhythm, so changing a filter or grouping does not trigger a read
  per control.
- Filters, metric, bucket, grouping and comparison live in the URL, so a view
  survives a reload and can be shared. Charts support drag-to-window, series
  selection from the legend, pinning and a key detail drawer. Desktop and phone
  each get their own layout.
- Usage facts now also keep a grain on the deployment's own calendar days, so a
  per-day read no longer folds quarter-hour rows. The grain is derived: it is
  rebuilt from the quarter-hour rows in one transaction when the time zone
  changes, and reads fall back to the quarter hours until that rebuild lands.
- Insights and the dashboard's KPI sparklines, model trends and usage rings now
  share one deferred SVG ECharts runtime. The former dashboard chart runtime and
  its vendor chunk are gone. Model series keep stable colours, legends highlight
  on hover, ring centres follow the selected slice, and animation is disabled
  under reduced motion.

## Usage accounting and pricing

- CPA's versioned accounting envelope is validated before OMC uses it. Input,
  output and cache counts are normalized only for complete, consistent
  partitions, and canonical output counts reasoning once: raw output 30 plus a
  separate reasoning 10 becomes 40, while a reasoning-inclusive output of 40
  stays 40.
- The raw vendor counts, their typed breakdown, the envelope version and the
  validation status are stored as immutable request evidence. Console request
  and cost reads, and the Agent/MCP capabilities, report the same accounting
  interpretation.
- Supplied accounting that is unsupported, invalid, inconsistent or
  unclassified is left unpriced and states its reason. Price editing is not
  offered as the remedy for it.
- Usage facts keep canonical, unresolved and raw input/output/total measures in
  all three permanent grains, so the evidence survives detail retention and a
  local-day rebuild. Historical rows keep their original counts, interpretation
  and locked amounts.

## Tokens per second

- TPS now defaults to including first-token latency. A deployment that never
  chose a mode gets the inclusive rate; choosing exclusion shows a warning that
  the narrower denominator can produce unusually high rates.
- One shared calculation serves request rows, the request drawer, JSON export
  and the Playground. When the token scope and the timing evidence do not match
  the selected formula, the rate is shown as unavailable together with its
  basis.
- Inclusion uses the canonical output total including known reasoning; legacy
  records fall back to the recorded grand total. Exclusion subtracts first-token
  latency only when the token scope matches the observed boundary, so hidden or
  inline reasoning without a content boundary reports exclusion as unavailable.
  The previous timing and rate heuristics are gone.
- Reasoning counts from Chat Completions, Responses and Claude Messages streams
  are preserved. The Playground treats a separate thought channel as a content
  boundary and inline `thinking` as sharing the reply's clock.

## OAuth workspace

- Credentials are grouped into one table per provider, following the shared
  primary-provider order, and each section sorts by a chosen quota column.
  Family and period columns are derived from the windows a section's credentials
  report, so a section only shows windows at least one of its credentials
  returns.
- Account names are masked until revealed, quota-cell tooltips carry the exact
  reset and capacity context, and reset credits are drawn in ink only where they
  are reported. A SIWC column appears only in a section that holds a Codex
  credential with SIWC state, and opens the credential's SIWC dialog from the
  badge or the row menu.
- Refresh quota is now a glyph on every refreshable row beside Details. The
  glyph is marked when a reading is stale or its last refresh failed, and the
  row no longer carries a second refresh control.
- Stale and disabled rows dim their cell content while the row's hover and
  selection fills stay continuous.
- The traffic (request count) column and its sort are removed; Insights reports
  request volume. A saved view or link that still names `requests-desc` falls
  back to name order.
- Phone cards show identity and state with the enable switch, then the readings
  the credential reports in two named columns. Windows the credential does not
  report and absent reset credits are omitted, labels wrap, and a lone last item
  takes the full line.
- The SIWC dialog is reduced to a status card (local status, binding, expiry),
  the use switch and the bind action. Explanations moved into info tooltips and
  binding is two numbered steps: open authorization, then paste the callback
  URL.

## SIWC

- A binding callback that is missing `code` or `client_id` is refused with
  `siwc_callback_incomplete` before any audit record or CPA call, and the
  pending binding session is kept. Provider error callbacks are still accepted.
- The `use_siwc` switch copy now says which requests CPA routes through the
  ordinary OAuth partition regardless of the switch: ChatGPT Alpha Search from
  v8.0.38, and Codex clients identified by their user agent from v8.0.40.

## Agent

- Answers are OpenUI programs drawn by the official `@openuidev` renderer. The
  console executes no model-authored code; the iframe sandbox, the Canvas Kit
  and their capture path are gone. Stored conversations keep their old
  `render_ui`, `render_view`, `render_canvas`, `render_chart` and `render_table`
  calls as calls that changed nothing, and no longer draw them.
- The answer and the composer form one 960px column; prose keeps a 760px
  reading measure and a drawn interface carries no console frame of its own. A
  table wider than a phone scrolls inside its own frame, never the page.
- In flight, one element moves: reasoning in its disclosure, a running call by
  its title, or the activity line when neither does. A finished answer's footer
  states success, duration and tokens; clock, round and call counts moved into
  the status line's tooltip.
- A form narrows to what its controls need, and the answer it was submitted with
  is drawn as the operator's own message. `prompt_openui` waits through the
  executor's existing pending, approval and audit path; `ask_question` remains
  the console's own question panel.
- An interface reads capability rows through a value-free data reference that
  resolves only against the current conversation, and may load only assets the
  console serves.
- The instructions that teach the language are generated from the installed
  packages and embedded in the server, so `pnpm check:openui-prompt` fails when
  the embedded copy goes stale.

## Quota

- Claude quota reads are serialized behind a process-wide gate, and a steady
  refresh reuses the plan for six hours and the reset grants for an hour, so it
  sends only the usage request. Other providers keep their concurrency.
- A 429 on the profile or usage read stops that read at the first refusal and
  pauses every Claude read for the longer of `Retry-After` and two minutes;
  `Retry-After` may be delta-seconds or an HTTP date and is clamped to one hour.
  A read inside the pause sends nothing and answers with the last good reading
  marked stale and deferred, without recording an attempt.
- The refused credential leaves the automatic schedule for five minutes,
  doubling with each consecutive 429 up to 30 minutes. A usable read clears the
  backoff, and the cap stays inside the reset-driven retry window.
- A refused grants listing waits its hour and does not pause usage reads. A
  failed read still never replaces the stored observation.
- A warmup round decides from the state it reconciled and stores that
  observation when nothing is due, so a credential already inside an active
  window costs no provider request between windows. Warmup now also honours the
  credential backoff that automatic quota refresh applies.
- Gemini 4 Argon is a recognized Antigravity capacity family. Gemini and
  Claude/GPT keep their five-hour and weekly windows; Argon reports a weekly
  window only.

## Plugins

- Embedded plugin pages render in Firefox again. The frame's parent is now an
  embedded, hashed same-origin asset instead of a `srcdoc` document, because
  Firefox blocks same-origin child frames in `srcdoc` documents under the
  console's `frame-src 'self' blob:` policy. The console sets the colour mode
  before navigating the child and updates it without reloading or touching the
  plugin's own theme attributes.
- An official-source entry is marked by the registry it belongs to rather than
  by its repository.
- The managed registry publishes repository-hosted candy artwork and complete
  store metadata for the OMC edition of Codex Candy Eval. Installing it still
  requires the usual third-party confirmation.

## Providers and settings

- Sidebar entries can be reordered within their group, by drag handle or by the
  earlier/later buttons. The arrangement is stored per group in `omc_nav_order`
  and applies to the expanded rail, the collapsed rail and the phone sheet.
  Hidden entries keep their positions, Show all never reorders, Reset order
  never unhides, and `/omc-settings` stays unhideable but movable.
- A provider row offers one editor action beside removal, and editing keeps the
  selected provider's identity.

## Build and security

- `dompurify` is overridden to 3.4.17, closing three advisories in the markdown
  and Mermaid render paths.
- `zod` moves to 4.6.6, and `undici` is pinned at 7.30.1 and 8.12.3. The
  `@ag-ui/core` instance that still asks for the unpatched zod 3 line is lifted
  onto 4.6.6 as well.
- `go-chi/chi/v5` moves to v5.4.0.
- `SECURITY.md` records the three override paths and the zod major-version
  caveat.
- The i18n catalogs are now one typed file per language per area, and `t()`
  accepts only the message ids the source catalog defines, so a typo or a stale
  id fails the type check instead of rendering as the id. Production builds take
  the English catalog's keys from the source catalog rather than repeating every
  id in the English chunk, and `web/src/i18n/README.md`, `STYLE.md` and
  `GLOSSARY.md` document the translation workflow, voice and per-concept terms.

## Upgrade notes

- Back up `.env` and the data directory or volume before upgrading; follow
  `docs/ops/sqlite-operations.md`.
- Two forward-only migrations run. `047_usage_facts_local_daily.sql` creates the
  derived local-day usage grain, and `048_usage_token_accounting.sql` adds
  nullable immutable accounting evidence to `usage_events`, an immutability
  trigger for it, and additive raw/canonical measures to all three fact grains.
  The schema advances to `048_usage_token_accounting.sql`.
- Neither migration backfills or reprices anything. Existing requests keep their
  original counts, interpretation and locked amounts; records without canonical
  evidence stay legacy and keep the established raw-count pricing policy.
- The local-day grain is derived from the quarter-hour rows and is rebuilt in
  one transaction when the deployment's time zone changes. Until that rebuild
  lands, per-day reads use the quarter-hour rows, so no data is lost, but a
  rebuild over a large history takes the time its quarter-hour scan takes.
- TPS defaults to including first-token latency. An install that never chose a
  mode shows the inclusive rate after upgrading; an explicit exclusion choice
  is kept and now carries a warning.
- A saved OAuth view or link that sorted by request counts falls back to name
  order, and request volume is reported by Insights.
- Agent conversations recorded before this release keep their old display calls
  as history that changed nothing; those calls are no longer drawn.
- A manual Claude quota refresh during a rate-limit pause shows the last reading
  marked stale instead of calling Anthropic. The pause and the per-credential
  backoff live in memory and reset when the console restarts.
- Compose continues to default to `latest`. After publication, pin this release
  with `wiziscool/oh-my-cpa:v0.3.10` or `wiziscool/oh-my-cpa:0.3.10`.
- The CPA baseline is unchanged: CLIProxyAPI v8.0.0 or later, with the same v8
  Management API surface.
