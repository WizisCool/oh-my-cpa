# Oh My CPA v0.1.4

## Plugin pages

- A trusted installed plugin page can call CPA's native v0 and v8 management
  routes and read the gateway model directory through
  `<base>/api/v1/plugin-host/`. Pages that read effective configuration or
  provider groups before calling their own plugin routes now load inside the
  console. Hosted requests to all three surfaces are rebased onto the console's
  base path.
- Native responses are not projected and can contain client and provider
  secrets. Install only trusted plugins: a page is same-origin with the console
  and acts with the signed-in operator's authority.
- A management key typed into a plugin page is compared with the stored CPA
  management key inside Oh My CPA. A wrong or empty key is answered `401`
  without a request to CPA, so mistyped keys no longer count toward CPA's
  failed-attempt ban, which previously could leave every CPA-backed console
  feature refused until the ban expired or CPA restarted.
- Only the key stored for the instance is accepted on this surface. When CPA
  also honours a different `MANAGEMENT_PASSWORD`, enter the stored key. A page
  that sends no credential still acts with the stored key; the model directory
  receives only the page's client Authorization.
- Every plugin page API read and write is audited as `plugin.route_call`
  without request payloads, path suffixes or queries, and responses are not
  cached. Configuration-affecting native writes are serialized with console
  writes and require an encrypted pre-write configuration backup; a backup
  failure blocks the write.
- Both outbound `api-call` bridges stay refused. Plugin pages remain
  unavailable in demo mode and are not Agent/MCP capabilities.

## Console fixes

- Tooltips anchored to status labels attach to the label itself.
- The provider editor's model field keeps a stable suffix while its endpoint
  model list loads.
- Collapsing the request list header from a wheel gesture no longer attempts to
  cancel a passive event.

## Upgrade notes

- Back up the persistent SQLite database and preserve its master key before
  upgrading; follow `docs/ops/sqlite-operations.md`. This release adds no database
  migration beyond v0.1.3 and does not change its retention defaults.
- Native writes from a plugin page keep CPA's last-write semantics. Do not edit
  the same configuration in a plugin page and an unsaved console draft at once.
- An address ban already in effect in CPA is not lifted by upgrading; it expires
  in CPA or clears when CPA restarts.
- Compose continues to default to `latest`. To pin this release after publication,
  use `wiziscool/oh-my-cpa:v0.1.4` or `wiziscool/oh-my-cpa:0.1.4`.
