# Oh My CPA v0.3.6

This release adds credential-scoped SIWC binding for existing Codex credentials,
Vertex service-account OpenAPI route editing, the Codex web search result cache
controls and plugin-provider model catalogs in the OAuth model-rule editors.
Plugin SVG artwork now follows the console theme.

## SIWC binding (CPA v8.0.35+)

- The credential detail drawer offers **Bind SIWC** and an explicitly confirmed
  **Rebind SIWC** for a uniquely resolved existing Codex OAuth credential.
- Binding is available for standalone local credential files only. Home mode,
  non-file backends and older gateways report it as unavailable, and there is no
  fallback to ordinary Codex login.
- The flow starts no loopback listener: paste the complete
  `http://127.0.0.1:1455/auth/callback` URL, including the issued `client_id`,
  even when that page cannot load. OMC forwards the URL unchanged after matching
  its state and redirect origin/path.
- Callback values are never stored in preferences or audit records. Attempt
  audits are fail-closed for start, callback and cancellation. Success requires
  completed status followed by safe credential readback; uncompleted attempts
  expire after five minutes.
- The credential list and the existing Agent/MCP credential read expose
  `siwc_bind_supported`, `use_siwc`, `siwc_bound` and optional
  `siwc_expires_at`. Stored material presence and expiry are not live validity
  checks. Binding, callback completion and unbinding remain operator-driven;
  Agent/MCP has no capability for them.

## Vertex service-account OpenAPI routing (CPA v8.0.34+)

- For Vertex service accounts only, the credential drawer, safe-field facade and
  confirmed Agent/MCP `oauth_set_credential_fields` edit `openapi`,
  `openapi_location` and `openapi_models`.
- `openapi` follows CPA's model-name detection or forces it on or off; an
  explicit off stays distinct from inheritance. An empty location uses the
  credential's location. Registered models are optional when provider-wide
  aliases already supply the names, and null returns any field to inheritance.
- Names CPA also registers from the credential's legacy `models` key are shown
  read-only. A model-list change takes effect when CPA reloads the rewritten
  credential file.
- Other credential kinds are refused before the write (HTTP 400) and at Agent
  preview. The service account and tokens are never projected.

## Codex web search result cache (CPA v8.0.34+)

- The Codex client behavior group now edits **Cache web search results**
  (`enabled`, default off), **Search result lifetime** (`ttl`; empty or `0` uses
  CPA's 24-hour default) and **Search result entry limit** (`limit`; default
  1024, `0` uses the default).
- Each control writes its own leaf through the existing revision-guarded,
  backed-up change set; the TTL is written as text and the limit as an integer.
  CPA validation refusals are shown with its reason.
- The copy distinguishes this session-scoped cache from prompt caching and from
  usage retention.

## OAuth plugin-provider model catalogs (CPA v8.0.34+)

- The Model rules editors request a catalog for any valid provider key,
  including plugin-owned providers served by CPA's plugin host or provider
  registry. Only model IDs and display names are projected.
- An unknown channel, or a gateway that predates plugin catalogs, leaves the
  catalog unavailable and keeps manual model entry; other upstream failures
  remain errors.

## Plugin artwork

- SVG plugin marks render as unframed, theme-colored glyphs in navigation,
  management cards and drawers, and hosted-page headings, so theme, hover and
  selected-state colors apply. Raster plugin marks keep their original colors,
  and the generic icon fallback is unchanged.

## Verification tooling

- Browser, probe and repository checks now run on pinned Playwright Test and
  Node's test runner with tsx. Scenario coverage, context-local fault
  boundaries, affected development selection and partition deadlines are
  unchanged.

## Upgrade notes

- Back up `.env` and the data directory or volume before upgrading; follow
  `docs/ops/sqlite-operations.md`. This release adds no SQL migration; the schema
  remains at `043_channel_model_prices.sql`.
- No new environment variables or preference keys are introduced.
- SIWC binding requires CPA v8.0.35 or later. Vertex OpenAPI overrides, the
  Codex web search result cache and plugin-provider model catalogs require CPA
  v8.0.34 or later; an older gateway stores the Vertex keys but ignores them,
  and leaves plugin catalogs unavailable. OMC's general CPA v8.0.0 Management
  API baseline is unchanged.
- Compose continues to default to `latest`. After publication, pin this release
  with `wiziscool/oh-my-cpa:v0.3.6` or `wiziscool/oh-my-cpa:0.3.6`.
