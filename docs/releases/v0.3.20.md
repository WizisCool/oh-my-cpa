# Oh My CPA v0.3.20

This release carries two things CPA v8 owns into the console — credential-scoped
connection reuse and each plugin login portal's own name and mark — and reads
plugin-store metadata in the language the console is set to. It repairs two readings
that were wrong: plugin artwork drawn at one text glyph inside a chip reserved for it,
and gateway log timestamps moved by the difference between two time zones. The pages
also stop keeping their own near-copies of one summary line.

## Connection reuse

- The provider editor carries CPA's `connection-pool` block, which is credential-scoped:
  a group default and a per-key override, on API-key providers and on OpenAI-compatible
  ones. `enabled`, `idle_conn_timeout` and `max_idle_conns_per_host` are the fields that
  reach the file.
- Inheritance resolves per field, not per block. A missing or null subfield follows the
  group, an empty block is an opt-in that turns on CPA's own defaults, and explicit
  `false` and zero stay explicit — zero is how the limits are turned off.
- Removing a key's block restores inheritance instead of writing a forced off state, and
  the editor never replays a resolved value. A key whose override happens to equal the
  group's current value keeps it as an override, because collapsing it would change what
  happens when the group default is edited later.
- Rotating a key keeps the settings that belong to that row: the draft names the stored
  row it was opened from rather than sending the old credential back beside the new one.
- The write goes through the existing revision-checked provider path and its encrypted
  pre-write copy; a pool field is not a way around either. Duration grammar is CPA's to
  validate, so OMC bounds the string and the integer and parses nothing twice.
- Not included: a global pool toggle, an OAuth credential control, and any pooling OMC
  performs itself. CPA still owns transport reuse.

## Plugin login portals

- CPA v8.0.51 publishes `oauth_provider_entries` beside the bare identifiers: the name
  and the logo each portal declares for itself. OMC reads it through the facade and its
  handwritten plugin DTO, and a login card now names and draws its own portal, so a
  plugin fronting several brands shows `Z.ai` and `BigModel` instead of two cards with
  one title and one mark.
- The identifier keeps the rules the bare list already had — trimmed, lowercased,
  pattern-checked, deduplicated, and dropped rather than truncated — because it names an
  upstream identity and a shortened one names something else. The name is handled the
  opposite way: it is either the text the plugin published or nothing, so an oversized
  one is dropped and the card falls back to the plugin's name.
- A portal's mark is inlined through the same fetcher as every other logo, and the
  projection additionally holds it to inline `data:image/*` artwork. That is the last
  place before a browser, and a deployment that fetches nothing a plugin names — the
  public demonstration — would otherwise leave a plugin-chosen URL in the response.
- The inlined-logo ceiling now measures what a base64 payload decodes to instead of its
  encoded text. Encoding was charged against an image-sized ceiling, so a logo the fetch
  path had already accepted and inlined could still be discarded on the way out.
- `pluginOAuthProviderLogos` prefers a portal's own mark for its key and keeps the
  plugin-wide logo for the plugin id and every other key, so credential, quota and usage
  rows resolve the artwork the card drew. Ownership is unchanged: every declared
  identifier still belongs to the plugin that declared it.
- CPA fills an empty entry name from plugin metadata, so a name that only repeats the
  plugin is that fallback arriving as text. A card shows the portal's label only when it
  says something the plugin's own name does not; otherwise it keeps its `${name} · ${id}`
  title rather than becoming a second identical card.

## Plugin store in the console's language

- CPA's store response may carry per-locale metadata. Locale tags keep their identity — a
  tag is never truncated into a different language — and unusable ones are dropped; the
  map is read in a deterministic order under the same cap as the rest of the list. CPA
  HTML-escapes these fields for its own console, so OMC decodes exactly once before
  bounding the text and validating URLs, and consumers still render the result as text.
- The metadata selector maps OMC's four reading languages explicitly. `zh` means
  Simplified (`zh-CN`, `zh-Hans`, then bare `zh`) and `zh-Hant` means Traditional
  (`zh-HK`, `zh-Hant`, `zh-TW`), so bare `zh` never supplies Traditional. Each field
  falls back to base metadata on its own, and never across scripts.
- Store cards, the installed list, the install and update confirmation and search all use
  that selection. Identity does not move with it: plugin ids, provenance, trust and
  install targets are unchanged, and an installed copy takes the catalog's translated
  name and author only when the listing is the same id with a matched install source. A
  catalog entry from another source cannot rename a local plugin.
- A store response from a CPA that publishes no translations keeps its base metadata.

## Credential workspace

- A provider section header ends with a divider under refined title type and a pill
  count, so the header and the quota table beneath it read as two things.
- On a phone the table's own header is not drawn, so a section carries a select-all
  checkbox beside its title; it states how many of that section's rows are selected.
- Table headers separate with one baseline rule under the head row and bottom-aligned
  cells, instead of a nested hairline in every cell.
- Antigravity's `Claude and GPT` group quota leaves the list table, so `Gemini` (5-hour,
  weekly) and `Gemini 4 Argon` (weekly) tile the width without squeezing. Nothing is
  discarded: the credential drawer's Quota tab still shows the full breakdown.
- Where a section groups columns under a family, a period header names the family in its
  tooltip and, on a phone, prints `{family} ({period})`.

## Plugin artwork

- The plugin list reserved a 44 px chip and each store card 48 px, and `PluginIcon` asked
  the shared artwork renderer for `1em`. That size is written as an inline style, which
  outranks the stylesheet rules that sized the chip, so every published logo was drawn at
  one text glyph inside an empty frame.
- The artwork now fills the chip its surface reserves, and each surface owns the size: the
  navigation rail keeps its 16 px, the fallback puzzle glyph keeps its own, and the store
  and the installed list get the 44–48 px they had already reserved.
- The browser probe measures rendered artwork against the chip that holds it on both
  surfaces. A size applied inside the artwork rather than by the surface does not pass.

## Page summaries

- `SummaryStrip` is one primitive below a page title: a total in tabular figures, `·`
  separators, and tonal items that carry a 6 px status dot. OAuth management's own copy
  moved into it, AI providers replaced a `providers · models · keys · headers` sentence
  with a count and a health breakdown, and API keys states its total with how many were
  used in the last day.
- AI providers counts the same rows its table shows, including the enabled state a pending
  switch has already moved, so the summary cannot disagree with the list under it.
- A text-only subtitle follows one measure everywhere: 12 px, 1.4 line height, tabular
  figures and the same offset from the title, so a page that states a sentence and a page
  that states a count no longer look like different components.
- `PageHeader` renders a text subtitle in a paragraph and a rich one in a container, so a
  summary node is no longer a `div` inside a `p`.

## Gateway log timestamps

- A CPA log timestamp without `Z` or a numeric offset is now shown as the wall clock CPA
  wrote. CPA's log response does not name the zone that wrote it, so no deployment-side
  setting can establish the instant; converting it by the console's zone moved every such
  line by the difference between the two, which is the eight hours in the reported case.
- Timestamps carrying `Z` or a numeric offset still convert to the effective display zone,
  fractional offsets included, and a raw log download is unchanged either way.
- `configureTimeZone` notifies its listeners only when the effective display zone actually
  changes, so a server-zone change no longer redraws every consumer for nothing.
- [Operations](../operations.md) drops the instruction to keep CPA's and OMC's deployment
  time zones equal. That instruction existed to make the old conversion come out right.

## Usage collection guidance

- The installation guides no longer state that CPA's usage queue has exactly one reader,
  and `OMCPA_USAGE_INGEST_MODE`'s `auto`, `subscribe`, `resp_pull`, `http_pull` and `off`
  are documented as what they are.
- `subscribe` holds a live subscription to CPA's usage channel, which broadcasts beside
  the destructive queue; the pull modes are the ones that take a record away. A
  deployment on `subscribe` therefore reads without consuming, which is what the blanket
  single-reader warning was wrong about.
- Probing availability still authenticates and never pops a record, in every mode.

## Upgrade notes

- Back up `.env` and the data directory or volume before upgrading; follow
  `docs/ops/sqlite-operations.md`.
- No new database migration is introduced. An install upgrading from v0.3.19 keeps schema
  version 056 (`056_usage_structured_details_repair.sql`), and existing data, costs and
  pending inbox payloads are untouched.
- No environment variable or Compose change is required. Connection-reuse settings are
  optional fields on the existing provider write: a provider that has none behaves as it
  did, and the upgrade edits no provider.
- Plugin login portals are read from CPA v8.0.51 and later. An older CPA omits
  `oauth_provider_entries`, and its cards keep the previous title and mark.
- The AI providers summary line is now a count and a status breakdown rather than
  `providers · models · keys · headers`. The counts themselves are still in the table.
- Compose continues to default to `latest`. After publication, pin this release with
  `wiziscool/oh-my-cpa:v0.3.20` or `wiziscool/oh-my-cpa:0.3.20`.
