# Oh My CPA v0.3.7

This release refreshes the console's visual system, lets existing AI providers
switch protocol drivers, and extends Vertex OpenAPI and Codex SIWC policy editing.
It also aligns Antigravity quota observations with CPA's reviewed Hub fingerprint.

## Console workspace

- Navigation sits on the canvas and each workspace on one inset panel. Static
  surfaces use quiet fills and hairlines; menus, popovers, dialogs and drawers
  retain soft shadows. Light and dark themes have clearer structural contrast.
- Provider sections, key cards and model cards share keyboard-accessible folding
  controls. Drawers retain their content while closing and keep a stable scrollbar
  gutter. Secondary header actions use named icon buttons and regain labels in
  the phone action menu.
- Key management now uses a responsive list, 24-hour used/idle filters, window
  totals and a drawer editor. Revision checks, masking and removal confirmation
  remain in place.
- Request records use roomier rows with speed before latency and tokens; image
  exports use the same model marks and vocabulary as the list. Theme transitions
  and reduced-motion behavior follow the updated visual system. Sarasa remains
  the default typeface.

## Provider protocol switching

- Change an existing provider's protocol driver in the edit drawer. The move uses
  one revision-guarded, backed-up configuration change and refuses stale or
  ambiguous targets and destination collisions.
- Credentials, supported model settings, key weights, proxies and runtime policies
  move with the provider. Unrelated configuration groups and hidden keys stay
  intact. Names, websites and icons follow the replacement provider IDs.
- The editor explains protocol-specific settings that cannot move and when a
  multi-key provider must split into separate destination rows. Probes and model
  pulls use the selected draft protocol.

## Vertex OpenAPI policy

- AI Providers exposes Vertex API-key OpenAPI defaults and location, plus optional
  per-model overrides. Model Rules and credential alias editors also expose
  per-alias overrides through safe facade fields and confirmed Agent/MCP edits.
- Inherit, explicit false and explicit true stay distinct. Model or alias overrides
  take precedence over credential defaults, then CPA's automatic model-name
  detection. Two aliases of one upstream model can use different policies.
- Unrelated edits and individual alias renames preserve stored overrides;
  ambiguous simultaneous renames are refused before writing. Clearing an override
  restores inheritance. Writes retain revision guards, encrypted configuration
  backups and policy readback. Existing service-account controls remain available.
- These controls require CPA support for the corresponding Vertex configuration
  fields. CPA continues to select endpoints and execute requests.

## SIWC local status and use

- Codex credential detail and existing Agent/MCP credential reads expose CPA's
  local SIWC status: off, valid or invalid. Missing or unrecognized metadata stays
  unknown; stored expiry or bound material never establishes validity.
- A Codex-only use switch edits the existing credential through audited, uniquely
  targeted, verified writes. Enabling requires an already-bound SIWC partition;
  disabling preserves both the SIWC partition and ordinary Codex credentials.
- A failed write verification refreshes the credential summary so a change that
  CPA already persisted is reconciled without a successful-save notification.
- Status reads do not refresh tokens or run inference. Bind/rebind and callback
  completion remain operator-driven. Older gateways without local-status metadata
  show unknown and leave the use control unavailable.

## Antigravity observations

- Quota and subscription reads use Hub 2.24.0 with its verified changelist
  1000335682. The daily subscription request omits `Accept`; quota-summary reads
  retain their existing header shape.
- Subscription enrichment failures leave independent quota windows available and
  the plan unknown. The observation change does not alter inference routing or
  introduce dynamic vendor-version lookups.

## Upgrade notes

- Back up `.env` and the data directory or volume before upgrading; follow
  `docs/ops/sqlite-operations.md`. No SQL migration is added; the schema remains at
  `043_channel_model_prices.sql`.
- OMC's general CPA v8.0.0 Management API baseline is unchanged. Use a CPA build
  supporting the newer Vertex policy and SIWC status/use fields for those
  controls; existing SIWC binding still requires CPA v8.0.35 or later.
- Compose continues to default to `latest`. After publication, pin this release
  with `wiziscool/oh-my-cpa:v0.3.7` or `wiziscool/oh-my-cpa:0.3.7`.
