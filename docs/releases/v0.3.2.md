# Oh My CPA v0.3.2

This release turns the dashboard into the operator's own surface: a live routing map of the
models called in the last minute, a board whose widgets are ordered, widened and hidden by
the operator, and a loading bar that reports only the work someone is waiting on. Custom
model prices can now differ per channel. The gateway baseline is unchanged: CPA
**v8.0.31** and CPAMC **v1.26.5**.

## Live routing

- **A map of the last minute.** The dashboard shows which models were called, through the
  gateway, and which credentials and providers answered. Each model sends one inbound line
  and each credential one outbound line; line width follows traffic, and the map separates
  the paths when several models and credentials are active.
- **Requests replay as they are stored.** Every request that is stored while the panel is
  open sends a packet from its model through the gateway to its credential, which holds the
  result for a moment and returns with that result's colour. A request CPA rerouted goes
  back to the gateway and on to the next credential. Cards and lines light as a packet
  passes and fade after it.
- **Cooldowns and failures.** A credential resting out a rate limit or an exhausted quota
  shows its countdown; a credential whose attempts all failed draws its outbound line in
  the error colour.
- **Rows age in and out of the window.** A model or credential slides in with its first
  request and out one minute after its last. A crowded map tightens and folds the remainder
  into one `N more models` row.
- **Phones do not mount the panel**, and issue neither its read nor its live connection. A
  narrow panel, such as one beside an open drawer, switches to a compact layout.
- Reduced motion updates the data without animating it.

## Dashboard arrangement

- The dashboard is one four-column board of twelve widgets: the six KPI tiles, Token trend,
  Model usage, live routing, token activity, credential quota and the provider list.
- **Customize layout** opens arrangement mode. Each widget gains a drag handle, earlier and
  later buttons for keyboard and touch, a width choice (a quarter, a half, three quarters or
  the full row, limited to what the widget can use) and a hide button. Hidden widgets wait
  in a tray above the board, each with its own restore button, and the widgets underneath
  stop taking input so arranging cannot open a drill-down.
- Arranging edits a draft: **Cancel** drops it, **Restore default** returns the catalog, and
  **Done** stores it as one document and confirms with a toast.
- The arrangement is the `omc_dashboard_layout` preference: every widget the console knows,
  in reading order, with its width and whether it is hidden. A widget a later release adds
  is missing from an older document and arrives at its default position, visible.
- Below 1100 px the board has two columns, and anything wider than a quarter takes the whole
  row. Phones keep no width control and still leave out live routing.
- Token trend and Model usage are separate widgets that read one shared query, so a model's
  colour matches in both.
- **Returning to a hidden console no longer replays the map.** Hiding the page ends every
  trip on the map, and only requests that finished after the page was last shown replay;
  requests that finished while it was hidden are counted on the rows instead.

## Pricing per channel

- **Channel-specific prices.** A custom price can be scoped to one recorded CPA channel for
  the same upstream model (ADR 0101), with its own input, output and cache rates and
  time-of-day tiers. The channel is the provider label recorded in usage events - the
  identity the channel multiplier already uses - so configuration rows sharing that label
  share a pricing scope; a routing prefix is not a channel.
- A model without an override keeps its shared price, and restoring the shared price returns
  it. The channel multiplier applies after either price.
- The price book shows one row per provider/model membership, labels a channel override or
  an inherited shared price, and keeps both scopes editable from that row.
- Automatic synchronization refreshes shared rates and never overwrites an override.
  Existing prices, recorded costs and their locked price versions are unchanged.
- Setting a price for a provider-prefixed call name no longer submits the prefix as a model
  identity, so a configured prefix no longer fails catalog validation.

## Instant updates and loading feedback

- **Changes arrive when they are stored, not on a timer.** Ingestion publishes a coalesced
  change signal after each commit that stored a request, and after each credential error,
  since a cooldown changes what the routing panel draws. `GET /usage/live` is a server-sent
  event stream that carries no records: `ready` on connect, `usage` at most once per 250 ms,
  and a heartbeat every 20 s. It ends after five minutes so the reconnect re-authenticates;
  readers are capped and the endpoint answers 503 past the cap. Without a collector
  (ingestion off, or the public demonstration) it answers 204 and pages fall back to polling.
- `GET /usage/routing` answers the window's attempts and the cooldowns in progress, projected
  through the same allowlist DTO as the request list; `after=<record id>` returns only what
  was stored since. A browser tab keeps one stream for every reader and closes it while the
  tab is hidden. The request list follows the same signal when auto-refresh is on.
- **The loading bar counts work, not traffic.** It now shows a first read with nothing on
  screen yet, an action invalidating data that last read successfully, and a manual re-read
  of a query nobody polls. Background polls no longer paint it, including the shell's health
  poll, ingest status, the heatmap, credential quota, providers, OAuth management and the
  request list's live re-reads. A poll after a failed read is still not counted, and a key
  change that also carries a new filter, page or manual sync still is.

## Upgrade notes

- Back up `.env` and the data directory or volume before upgrading; follow
  `docs/ops/sqlite-operations.md`. This release adds migration `043_channel_model_prices.sql`:
  a channel discriminator on the append-only price history, whose existing rows default to
  the shared scope, and the override table with its history triggers. Existing prices and
  recorded costs are not rewritten.
- No new settings and no environment variables. The arrangement and the existing display
  settings are console preferences stored by the server.
- The live endpoints are additive: a deployment that cannot hold a stream keeps its existing
  poll, and no configuration is needed for either behaviour.
- Channel overrides are custom rates. Automatic OpenRouter synchronization does not create
  them, and the agent pricing capabilities continue to operate on shared prices.
- Compose continues to default to `latest`. After publication, pin this release with
  `wiziscool/oh-my-cpa:v0.3.2` or `wiziscool/oh-my-cpa:0.3.2`.
