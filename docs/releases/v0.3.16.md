# Oh My CPA v0.3.16

This release serves new installations at the site root, lets an operator name every
credential, adds a request-record retention setting that returns the freed space to
disk, cuts console startup and page-switch cost roughly in half, and fixes the
dashboard activity strip opening two readings at once.

## Console served at the site root

- A new installation with no `OMCPA_BASE_PATH` serves the console at `/`, so a plain
  Docker deployment is reachable at `IP:port` and a reverse proxy can forward the site
  root without prefix handling.
- `OMCPA_BASE_PATH` remains the sub-path setting. Runtime configuration, Compose
  templates, environment examples, health checks, the Vite development server and the
  embedded SPA runtime all agree on the same mount.
- Existing deployments are not migrated or aliased: an explicit `OMCPA_BASE_PATH`
  survives `docker compose pull` / `docker compose up -d` and updater container
  replacement, so their URL, cookies, PWA identity and proxy rules stay valid.
- A fresh root installation has no `/omc` mount; `/omc` only reaches the generic SPA
  fallback.

## Operator-assigned credential names

- Any credential CPA reports can be renamed from OAuth management. `credential_display_names`
  (migration 052) stores one operator-assigned name per credential, keyed by
  `(instance_id, file_name)` and versioned like `client_key_aliases`. The name is Oh My
  CPA metadata: it lives beside CPA's note rather than replacing it, is never written
  into the auth file, and survives the credential's removal from CPA.
- A named row leads with its name and keeps the masked account beneath it; an unnamed
  row leads with the masked account as before. The note appears in a tooltip on its own
  glyph, and the auth file name no longer appears in the list — the details drawer and
  the duplicate-name warning still carry it. A fixed trailing slot reveals the rename
  glyph on hover, so nothing moves when it appears, and the new Edit glyph beside
  Details opens the drawer on the configuration tab.
- Request records, credential filters, Insights and the dashboard resolve a credential
  through one guarded resolver that shows the name only when the file's provider matches
  the record, so a reused `auth_index` cannot attribute one account's name to another.
- Provider section headers now carry the icon, name and credential count; the
  per-status tally and quota note are gone, and rows state their own status.
- `PUT /api/v1/management/auth-files/display-name` is audited fail-closed, answers `409`
  on a stale version or an ambiguous file name and `404` for a file CPA does not report.
  The auth-file DTO gains `display_name` and `display_name_version`.

## Request-record retention and space reclamation

- OMC Settings → Data Retention sets how long request records are kept: 7, 14, 30, 60,
  90, 180 or 365 days, or "Keep forever". A pick is saved at once; shortening it asks
  first, because the records past the new horizon are deleted for good.
- The value is stored in `usage_retention_settings` (migration 051) and read by every
  pass, so a change needs no restart. Until the console saves one,
  `OMCPA_USAGE_RETENTION_DAYS` applies; once stored, that value wins. The payload
  horizon keeps its own environment setting and is not offered in the console.
- Usage maintenance is now started by the application rather than by the capture
  pipeline, so stored records are still folded into the permanent usage facts and rolled
  out of retention with capture off or no gateway configured.
- The System page's storage card reports the horizon in force, the oldest record, rows
  deleted, the pass schedule and whether the file returns freed space.
- The database is opened with `auto_vacuum = INCREMENTAL` and each retention pass ends
  with a bounded `PRAGMA incremental_vacuum`, so the file shrinks by what the pass
  deleted. A database created by an earlier release stays in `NONE` mode, where deleting
  only frees pages for reuse, until it is rebuilt once with the compaction described in
  `docs/ops/sqlite-operations.md`; the System page reports which mode the file is in.
- Deletion is clamped to the cutoff in force, so a lengthened or disabled policy stops
  removing rows; a retention write is audited (`system.data_retention`) before it is
  stored and refused when that record cannot be written. A console sends the horizon it
  confirmed against, and a write whose expected horizon no longer matches is refused
  with `409 usage_retention_changed`.

## Faster console startup and page switches

- Route-only UI modules no longer load at startup, the workspace's dynamic icon
  directory ships as one deferred catalog, and the provider and OAuth editors load on
  first use while keeping their drafts and closing motion.
- A recognized module-load failure for a deferred surface keeps the page and its draft,
  with inline reload recovery; other render errors still reach the route diagnostic
  boundary.
- Measured on paired immutable production snapshots (ARM64 host, Chromium 151,
  1440×900, 4× CPU slowdown, 60 ms / 20 Mbps link): startup static JavaScript fell from
  3,098,852 to 1,384,683 bytes raw (−55.3%) and from 804,733 to 448,443 bytes gzip
  (−44.3%); warm navigation medians fell from 3,586 to 1,460 ms on the Dashboard
  (−59%), 2,097 to 1,128 ms on OAuth management (−46%) and 1,079 to 823 ms on
  Providers (−24%). Total emitted JavaScript grew about 0.8% as a partitioning
  trade-off, and other routes do not all show reliable runtime improvements.

## Dashboard provider activity hints

- Hovering a provider's activity strip now reads the block under the pointer. The
  whole-history list opens only for visible keyboard focus, so a pointer crossing the
  gaps between blocks no longer stacks two hints.
- The shared `Tooltip` gained a focus-only mode that keeps every shared dismissal (blur,
  Escape, scroll, outside press, window blur), and each history reading stays on one
  line.

## Upgrade notes

- Back up `.env` and the data directory or volume before upgrading; follow
  `docs/ops/sqlite-operations.md`.
- Two migrations apply on first start: `051_usage_retention_settings.sql` and
  `052_credential_display_names.sql`. An install upgrading from v0.3.15 moves from
  schema version 050 to 052; existing data and settings are untouched.
- Deployments that set `OMCPA_BASE_PATH` keep that mount unchanged. An installation
  that relied on the previous `/omc` default now serves at `/`: set
  `OMCPA_BASE_PATH=/omc` before upgrading to keep the existing URL, cookies and proxy
  rules, or move bookmarks and proxy rules to the site root deliberately.
- Request-record retention keeps its previous defaults: 90 days, with 7 days for
  captured payloads. Nothing is deleted differently until a value is saved in the
  console.
- A database created before this release keeps its current `auto_vacuum` mode until it
  is compacted once; deletions still apply and their freed pages are reused meanwhile.
- Compose continues to default to `latest`. After publication, pin this release with
  `wiziscool/oh-my-cpa:v0.3.16` or `wiziscool/oh-my-cpa:0.3.16`.
