# Oh My CPA v0.3.13

This patch fixes upgrades of existing databases in deployments with a read-only root
filesystem, including both release Compose files. It supersedes the withdrawn v0.3.12
release (Issue #364).

## Migration backup restore

- The mandatory pre-migration backup restore check creates its private temporary
  directory beside the encrypted backup, on the writable backup volume. It no longer
  depends on the operating system's temporary directory being writable.
- Encryption, checksum verification, restore validation and migration ordering are
  unchanged. Plaintext snapshot and restore workspaces are removed before returning.
- Existing Compose installations can upgrade without adding a `/tmp` tmpfs or making
  the container root writable. No new migration is introduced; upgrades from v0.3.11
  still apply migration 049 after the encrypted backup has passed its restore check.

## Upgrade notes

- Preserve the data directory or volume, master key, database/WAL files and existing
  backups. Follow `docs/ops/sqlite-operations.md` before upgrading.
- If the updater rolled back the failed v0.3.12 upgrade, upgrade the restored instance
  directly to v0.3.13. If a manual v0.3.12 deployment is crash-looping, stop the failing
  console before upgrading to prevent repeated backup creation.
- The reported restore-directory failure occurs before migration SQL is applied.
  Repeated failures can still accumulate encrypted backup/checksum pairs and consume
  disk space. Successful migration-backup validation resumes the configured retention
  policy; do not delete the database or bypass the backup check to recover startup.
- An instance already running v0.3.12 successfully can upgrade directly to v0.3.13;
  do not blindly downgrade a database whose migrations have already completed.
