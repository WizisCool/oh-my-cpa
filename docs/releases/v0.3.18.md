# Oh My CPA v0.3.18

This release adds a Routing board that draws CLIProxyAPI's priority tiers and applies a
whole arrangement against the revision it was arranged on, carries Codex and xAI
WebSocket transport from the provider editor to each request record, and gives every
route its own loading frame. Quota cards keep counting down a window that is already
full, plugin buckets read the name their author published, and a stacked request record
names its caller key on a phone.

## Routing board

- `/routing` states the order CPA tries credentials in. Every provider key,
  OpenAI-compatible provider and OAuth credential is a card, and a tier is the set of
  cards that share one `priority`, drawn highest first. The board opens with the request
  entry above the tiers and closes with what happens when every tier is unavailable:
  an error now, or after the configured retry rounds.
- Cards move between tiers by dragging them onto a gap or a tier on a desktop. The card
  menu moves one a tier up or down and splits it out of a shared tier. Every move is
  announced, so the order can be read without watching the drag.
- The within-tier strategy is stated on each tier, and a weighted tier carries one
  weight per key. Under fill-first, CPA's internal auth ID decides which card fills
  first and OMC cannot see that ID, so a strict A → B → C order needs one tier per card;
  the tier says so rather than implying an order it cannot promise.
- The model lens previews one model's route: tiers that cannot serve it are marked
  skipped and each remaining card states its expected share. The preview cannot see
  session-affinity pins, live cooldowns or transport preferences, and a model read that
  fails stays unknown rather than marking credentials ineligible.
- Gateway policy collects the settings that apply to every tier — within-tier strategy,
  session affinity and its TTL, retry rounds, retry credentials and interval, cooldown
  behaviour and the transient-error cooldown.
- Edits stay a local draft: the bar counts the changes and **Review** lists them as
  `priority 3 → 1` or `weight 1 → 4`. Leaving the page asks before discarding a draft,
  and closing the tab warns.
- Applying is bound to the revision the arrangement was made on. `GET
  /api/v1/management/routing` returns that revision, computed from routing-relevant
  fields only, and `PATCH` takes it with the changes alone. A board changed elsewhere is
  refused with `routing_conflict` (409) before anything is written, and the toast
  offers a reload.
- The write keeps the existing boundaries: the routing audit attempt is recorded first
  and nothing is written if that fails; one configuration write then covers provider
  priorities and weights together with the routing settings, taking one encrypted
  backup with reason `routing_plan`; each OAuth credential is patched with its identity
  precondition and readback, stopping at the first failure. CPA has no transaction
  across those steps, so the result names each target `applied`, `failed`, `uncertain`
  or `not_attempted` instead of claiming a rollback.
- After a submit, editing and applying stay locked until a read confirms what landed. A
  readback that fails says so and offers a reload rather than inviting a second write.
- Cards whose tier is unchanged keep their stored priority where the numbering allows,
  and runtime-only credentials keep a fixed priority. An arrangement that cannot fit
  between fixed priorities is refused with an explanation instead of being half
  applied. New tiers stay inside CPA's priority range, with smaller gaps near its limits.
- A source that cannot be read is named on the board rather than silently dropped, and
  demo mode serves the board while refusing the write.
- The shared Agent surface gains `routing_read` and `routing_apply`; the apply
  capability previews the same plan against a revision and writes after approval.

## WebSocket transport

- The provider editor offers CPA's per-key `websockets` switch for Codex and xAI, with
  copy that says it applies only when a client calls `/v1/responses` over a WebSocket.
  Meta keeps it out of reach: CPA decodes the field there but has no WebSocket executor,
  so a submit naming it is refused with `400`.
- Turning the switch off removes the key from the file, and a save that does not mention
  it leaves the stored value alone. The provider list marks a key that has it on.
- Each request record states the transport that carried it. A WebSocket executor means
  WebSocket whatever the stream flag says; otherwise `stream` separates streaming HTTP
  from a single HTTP payload, and a record carrying neither shows `—`.
- The mode column and the stacked sheet mark WebSocket requests beside the existing
  non-streaming mark; streaming HTTP is the ordinary case and stays unmarked. The detail
  drawer names the transport above the raw executor type.
- A `transport` filter narrows the list server-side, so counts, latency and failure rates
  follow it. It is available in the filter drawer, as a chip and in the URL.
- The demo seeds Codex WebSocket traffic.
- Not included: a per-key "no recent WebSocket requests" hint, and telling a downstream
  WebSocket that fell back to HTTP apart from one that did not. Both need CPA to report
  the downstream transport in its usage record.

## Route loading frames

- Every route used to share one fallback, a page head and six generic rows, so a
  dashboard, a settings stack and a request table all began as the same frame. A route
  now names the body its frame draws — `list`, `table`, `panels`, `workspace` or the
  dashboard's own tile board — and an unlisted route falls back to `list`.
- `PageLoading.tsx` holds those bodies, so the download frame and the page's first read
  draw the same shape. Dashboard, System and Routing keep their real page header while
  the first read is in flight.
- A desktop list draws skeleton rows under its real column headers instead of a spinner
  over an empty table.
- A navigation whose module was already downloaded renders immediately. `React.lazy`
  suspends on first render even then, and React holds a revealed fallback for up to half
  a second, which was the flash on every preloaded switch.
- Nested placeholders add no second `role="status"` and share one document-wide pulse, so
  the handover from route frame to page frame does not blink.
- Time-range pickers stay inert until the stored window has been read, so a fallback is
  never written back over it.
- Background refreshes, pagination and filters are unchanged: pages keep their previous
  rows and the app-wide progress bar.

## Quota readings

- A reset countdown is drawn from the reset time upstream reports, no longer gated on
  the remaining share rounding below 100%, so a five-hour or weekly window that just
  refilled still says when it renews. A reading with no reported reset keeps no
  countdown, and the reset accuracy markers are preserved.
- A plugin bucket's label is resolved through `displayName`, `display_name`, `window`
  and finally its bucket ID, so a bucket that publishes only a readable window no longer
  shows a synthetic ID. Period keywords are translated only when `window` names a known
  fixed duration: a free-form name such as `WEEKEND` keeps its meaning, and an unknown
  period prints verbatim rather than being folded into a week or a month.

## Caller key on stacked records

- Below the stacked-record width (container ≤ 920px), the quiet line of each record
  names the caller key beside the verdict, so a phone no longer defers it to the detail
  drawer. The cell takes only the room the line leaves and ellipsizes, so a long
  fingerprint key keeps the record at three lines.

## Upgrade notes

- Back up `.env` and the data directory or volume before upgrading; follow
  `docs/ops/sqlite-operations.md`.
- No new database migration is introduced. An install upgrading from v0.3.17 keeps
  schema version 052 (`052_credential_display_names.sql`), and existing data and
  settings are untouched.
- No environment variable, Compose file or configuration change is required. Routing
  adds a console page and three management endpoints — `GET` and `PATCH
  /api/v1/management/routing`, `GET /api/v1/management/routing/models` — that read and
  write the priorities and settings the configuration editor already owns. Reading the
  board changes nothing until a plan is applied, and an applied plan writes an encrypted
  configuration backup first.
- Compose continues to default to `latest`. After publication, pin this release with
  `wiziscool/oh-my-cpa:v0.3.18` or `wiziscool/oh-my-cpa:0.3.18`.
