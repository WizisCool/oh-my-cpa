# Oh My CPA v0.1.2

## Model Square

- Model Square replaces Quick Start with a read-only directory of the Call Points
  advertised by CPA's live model list, grouped by manufacturer.
- The directory shows model prices and provides model details, 24-hour request
  counts and bundled reference metadata where an exact identity is known.
  Missing facts remain unknown; advertised availability does not guarantee that
  an inference request will succeed.

## Plugin pages and management

- Plugin-registered pages appear in the sidebar and open inside the console
  through an authenticated, same-origin host. The management key stays on the
  server and the host restricts the routes it forwards.
- Plugin navigation separates installed plugins, the store and plugin pages.
  Settings are edited directly, with empty values falling back to the plugin's
  declared defaults.
- Plugin row actions use consistent controls, and authentication-provider
  connections use the plugin-declared provider identity.

## Permanent dashboard statistics

- Dashboard statistics are retained permanently, independently of request records
  and captured payloads. Existing retained records are folded into usage facts by
  the background maintenance loop; totals remain available while it catches up.
- The dashboard adds an All time range. Opening request details from that range
  uses the request list's longest preset, 90 days, rather than implying that
  individual records are kept forever.
- Request records default to 90 days of retention, and decoded captured payloads
  default to 7 days. Cleanup does not remove a request record before its statistics
  have been folded into permanent facts.

## OAuth model rules and development

- The OAuth workspace groups model aliases and exclusions under the same provider
  identity. Providers declared by authentication plugins use their canonical
  identities for these rules as well as their connections.
- Exclusions apply before aliases, so an alias cannot restore an excluded upstream
  model. Empty exclusions remove that provider's rules.
- The development server redirects the bare `/omc` path to `/omc/`, preserving
  sub-path asset loading.

## Upgrade notes

- **Review retention settings before upgrading.** The default
  `OMCPA_USAGE_RETENTION_DAYS` changes from 400 to 90. The new
  `OMCPA_USAGE_INBOX_RETENTION_DAYS` defaults to 7; a value of `0` makes decoded
  payloads follow request-record retention. With neither variable set, maintenance
  removes request records older than 90 days once their statistics are folded,
  and decoded payloads older than 7 days.
- To retain the previous policy, set `OMCPA_USAGE_RETENTION_DAYS=400` and
  `OMCPA_USAGE_INBOX_RETENTION_DAYS=0` before upgrading. Dashboard statistics
  survive subsequent request-record cleanup, but statistics for records deleted
  before this upgrade cannot be recovered. Deleted records and payloads cannot
  be recovered without a backup.
- Back up the persistent database and preserve its master key before upgrading.
  Migration `migrations/035_usage_facts.sql` runs through the normal startup
  migration and backup gates. Existing request records are folded into the new
  tables after startup; do not rewind migration history when recovering an
  installation. Follow `docs/ops/sqlite-operations.md` for backup and recovery.
- Cleanup frees SQLite pages for reuse but does not shrink the database file.
  Compaction remains an explicit operator action.
- Compose continues to default to `latest`. For a version-pinned deployment, use
  `wiziscool/oh-my-cpa:v0.1.2` or `wiziscool/oh-my-cpa:0.1.2` after publication.
  Both `linux/amd64` and `linux/arm64` are distributed through Docker Hub.
