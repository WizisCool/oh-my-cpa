# Oh My CPA v0.3.26

This release turns credential window warmup into scheduled tasks that wake the cheapest
priced model, reads a model-scoped cooldown separately from a credential-wide one, and
opens CPAMC-native plugin pages the way the console they were written for does. The plugin
store gains an explicit refresh and a bulk update, OAuth management gains a sign-in drawer
grouped by publisher and a section order you can drag, and provider model pulls ask each
family's own API root.

## Warmup tasks

- **A warmup is a task.** A task names one credential and one trigger: after a quota
  window resets, daily at a chosen time and zone, or every N hours from an anchor. OAuth
  management's **Warmup settings** drawer owns the list; the credential drawer no longer
  carries a second copy, and its credential picker groups by provider.
- **Auto picks a price, not a name.** A task's model stays empty by default and the run then
  sends the cheapest model the price book prices above zero, preferring the credential
  channel's own rate over the shared book. A zero rate is skipped rather than preferred: a
  free model is one that never runs the metered request that starts a window. An OAuth alias
  is ranked by the model it reaches while the alias stays what is sent, and image-generation
  models are not warmup candidates. When the book prices none of the candidates, the lightest
  name answers as before.
- **The scheduler supervises the run.** A run's record is written before the request is sent,
  and a run whose record cannot be written is not sent. A task deleted a moment earlier sends
  nothing, a task switched off does not run on schedule, and a task cannot be deleted while
  its run is in flight. Disabled and unavailable credentials are refused as
  `credential_disabled` and `credential_unavailable` instead of being woken, and a run the
  scheduler skips is logged instead of disappearing after its marks advanced.
- **Runs are visible.** Each task keeps its newest 50 credential-pinned runs with outcome,
  latency and token counts; clearing requires a task id, and a deleted task closes its open
  editor. A failed quota read waits five minutes, and a credential's model list is read once
  per sweep instead of once per provider scan.
- **Every row draws the portal that issued it.** The catalogue reports `oauth_provider` and
  the mark comes from the console's single credential-brand resolver, so a plugin fronting
  several brands no longer draws its whole logo on a credential one of its portals issued.
- The demonstration dataset is regenerated, and its warmup instants no longer drift: the
  export re-base holds a warmup catalogue account on the fixture clock, as it already held a
  quota reading, so two runs a minute apart produce the same bytes.

## Cooldown scope

- CPA publishes two cooldown scopes, the credential and a single model. The console decoded
  only the credential pair, so a 429 CPA cooled on one model left the Quota page reporting a
  healthy credential. Both scopes are now decoded and stored, and one event carrying both no
  longer overwrites either.
- **A model cooldown is partial.** The Quota page lists each resting model with its own
  recovery and retry instant and CPA's backoff level, and reports the credential as partly
  affected rather than blocked; the dashboard and OAuth workspace show the same state. CPA
  aggregates model quota into the credential's quota and projects credential quota onto the
  reporting model; both are recorded as credential evidence and kept out of the model-scoped
  view.
- **One model is listed once.** CPA compares cooldown keys without case and migrates an
  OAuth alias to the upstream model it reaches, while events already stored keep the spelling
  they arrived with. Cooldowns are grouped by trim, case-fold and the upstream model the
  spelling resolves to, keeping the newest row's spelling and the later recovery time. A
  plugin-shaped credential-quota event stays credential evidence and never becomes a
  model-scoped cooldown.
- Credential-wide clearing stays credential-wide: an expiry or restored reset does not erase
  another model's active cooldown, and the routing view applies its scope filter before
  picking the newest row, so a later aggregate cannot hide an earlier credential cooldown.
- The quota drawer's cooldown banner gives the clear button its own full-width row on a
  phone, and the window label its own line so a countdown is not broken mid-unit.

## Plugin store and plugin pages

- **The store has a refresh.** A Refresh action reads the registry again with
  `refresh=true` forwarded to CPA, and the installed list's Check for updates shares that
  request. Repeated clicks coalesce, an ordinary in-flight read is cancelled, the shared
  store cache and navigation reminder update on success, and a failure keeps the visible
  catalogue and filters. Partial source failures and upstream retry times are reported, and
  the result word says what the available store data shows rather than asserting every
  plugin is current. Older CPA versions may ignore the parameter and keep their own cache.
- **Update all.** More than one available update now offers a single confirmation listing
  each plugin's artwork and version change. Updates run sequentially, third-party
  confirmations still apply, an entry blocked on authentication is reported beside the
  successful ones instead of silently skipped, and each outcome is named individually.
- **Plugin pages open the way CPAMC does.** A page written for CPAMC reads the console's
  reading language from its parent document and the gateway credential from `cli-proxy-auth`
  in browser storage. The plugin frame's parent document now carries the console's
  `<html lang>` beside the colour mode and follows live switches, and the console mirrors
  the stored credential into CPAMC's own entry before the frame loads. Sign-out, a refused
  session check and the next sign-in withdraw it.
- The mirror's source is a session-only, `no-store`, demo-refused
  `GET /api/v1/management/cpa-credential`, audited as `cpa_credential.reveal` and answering
  nothing when that audit cannot be written. The console reads it once per session, and the
  plugin page's reload control retries a failed read. A page's explicit credential is still
  judged inside OMC before CPA is called, so a wrong or empty one cannot spend CPA's
  failed-attempt ban.
- Saved GitHub token additions, replacements and removals invalidate the in-memory release
  cache immediately instead of waiting for its TTL, and the plugin authentication settings
  link to the token configuration.
- The plugin page head names the destination: the store tab is headed Plugin store, while
  the installed list and settings keep Plugin management.

## OAuth management

- **Sign-ins are grouped by who publishes them.** The connect drawer draws Built-in and
  Plugins sections, and a plugin-declared portal carries OMC's own badge when the store
  proves an OMC plugin published it, otherwise a plain plugin tag — the same distinction the
  plugin management page draws. A missing store read leaves every plugin portal simply a
  plugin portal. The per-tile flow tag is gone; the drawer shows the flow's own steps once
  a sign-in starts.
- **Authorizations outlive the drawer.** The strip above the list now carries its own
  cancel, so a sign-in started from a panel that has since been closed can be ended without
  reopening it. A cancel CPA refuses is reported as such while the result keeps being
  checked.
- **Provider sections can be dragged.** The band that names a provider is the grab surface,
  as a window is moved by its title bar; on touch the grip carries the drag so a finger on
  the band still scrolls. The arrangement lives in the `omc_oauth_section_order` preference,
  applies over every provider the workspace has, and feeds both the page cut and the
  drawing, so a section split across two pages continues in the same place on both.
  Providers the preference does not name follow in the console's fixed order. CPA priority,
  weights and routing are untouched.

## Providers, models and insights

- **Model pulls ask the family's own root.** The provider editor built the directory URL the
  OpenAI way, so an Anthropic or Gemini provider whose base URL omits the version segment
  could not list models — Gemini never reached `/v1beta/models` because its refusal there was
  not the 404 the old fallback stepped over. The directory now comes from the family's own
  API root (`/v1/models` for Anthropic, `/v1beta/models` for Gemini), the same derivation the
  connectivity probe uses. OpenAI shapes stay as fallbacks for a relay that republishes the
  directory, and remain the whole answer for the families that speak that dialect. Each
  versioned directory is asked for one full page, and only a 404 continues the ladder, so a
  rejected key is never sprayed across paths. Google resource names are reduced to the id CPA
  routes; a provider that routes by a path of its own keeps it.
- **Provider provenance is cached.** Model Square could advertise plugin models without
  provider sources because page-request enrichment stopped after eight credential lookups or
  five seconds. Provenance now loads for every enabled credential in the background and is
  served from an in-memory cache refreshed at startup and once a minute, keeping the last good
  cache on operational failure and reading no credential files for display. A missing
  optional endpoint is treated as partial provenance, and a manual catalogue refresh publishes
  the cache before it answers.
- **Insights credit the connection that answered.** CPA labels every API-key request with its
  protocol family, so a provider the operator named AnyRouter arrived as `claude` and the
  ranking printed Claude's brand beside the channel's traffic. A row whose credential exactly
  one configured provider publishes now belongs to that provider, and the comparison period is
  re-keyed the same way; an index nobody claims, or one two providers both publish, keeps CPA's
  label rather than receiving a guess. The rhythm read translates a provider narrowing into
  the credential vocabulary the request records use.
- **The model badge lists call points.** A provider now publishes the names a client can
  actually request: an entry's alias, else its request model, with the request model kept
  beside an alias (`codex-auto-review ← gpt-5.6-luna`). A provider with two entries behind one
  upstream model no longer repeats that name.

## Console details

- **The first painted frame is the console's own ground.** A resumed phone tab used to show
  the browser's white canvas until the stylesheet and bundle arrived, and a light console
  painted dark until the theme provider ran. The entry document now carries both shipped
  grounds and the matching `color-scheme` ahead of everything else, plus a parser-time script
  that reads `omc-theme`, resolves `system` against `prefers-color-scheme` and sets
  `data-theme-mode`, so the stylesheet's light block applies on its own first paint.
- **The wheel no longer changes values it merely crosses.** `NumberInput` steps its field only
  while the field holds the caret; unfocused, the wheel is not consumed and the page scrolls
  where it was going. The routing weight chip steps only while its editor is open.
- **Fetched artwork holds its box.** Plugin logos, provider and credential marks, catalog
  SVGs, uploaded icons and backup-storage marks share one `RemoteImage` that keeps the mark's
  geometry with the console's existing first-load placeholder. Cached artwork appears on the
  first paint, inline `data:`/`blob:` sources skip the wait, and a source that cannot be drawn
  releases its box and advances the fallback chain.
- **Long labels fit.** The warmup window picker is a vertical list and its label wraps
  instead of being clipped to its middle, and an action menu now reads its trigger's place and
  opens toward the wider side, so the OAuth management menu no longer starts off-screen on a
  phone.
- **Credential names on the routing board are masked** through the identity projection the
  OAuth workspace and request records already use, with click-to-reveal through a shared
  `MaskedText`; an address-shaped name stays masked even when the auth-file read has not
  answered. The gateway's own naming is unchanged for the Agent.
- **`never` joins session-affinity rebind.** CPA's third
  `routing.session-affinity-rebind-on` value keeps an established session on its bound
  credential across every failure, and now carries a label in the configuration editor
  instead of appearing as a bare value.
- Switch fields in the configuration form grid keep their labels on one line.

## Upgrade notes

- Back up `.env` and your SQLite database or volume before upgrading; refer to
  `docs/ops/sqlite-operations.md`.
- Database migration `059_model_cooldowns.sql` extends `error_events` with the model-scope
  columns. It is forward-only and runs at startup.
- **Warmup tasks replace the per-credential policies.** Existing policies are not converted:
  the warmup drawer starts with no tasks, and a deployment that was waking credentials must
  create one task per credential it still wants woken. Run history from the retired schedule
  is neither read nor trimmed.
- `omc_oauth_section_order` is a new UI preference; it needs no schema change.
- Plugin pages written for CPAMC now find the gateway credential in `cli-proxy-auth` browser
  storage. That entry holds the management key, which remains the single deliberate exception
  to the rule that keys stay out of browser storage; sign-out withdraws it.
- Two console tabs are not kept in step: if one signs out and signs in again while another
  stays open, a plugin page in the older tab may prompt for a key until that tab reloads.
- The plugin store's refresh parameter is optional for CPA. A gateway that ignores it keeps
  its own release cache.
- Container images are available on Docker Hub as `wiziscool/oh-my-cpa:v0.3.26` and
  `wiziscool/oh-my-cpa:0.3.26`.
