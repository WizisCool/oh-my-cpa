# Oh My CPA v0.3.25

This release adds model-authored HTML pages to the Agent, turns update checks into a
scheduled sweep the operator controls from settings with reminders pushed to the open
console, and gives plugin updates a place in the installed list. Credential artwork now
comes from one identity that prefers the issuing OAuth portal, OAuth failures keep their
actionable reason, and pricing reads a credential's own model aliases.

## Agent HTML pages

- `present_html` is a new Agent display tool. The model passes one complete document of at
  most 64 KiB, the call ends the turn, and the console draws the page where the call sits —
  the page, its source, an expanded view and a download.
- A whole HTML or SVG document that still arrives as answer text offers the same page, so
  stored turns and a model that ignores the tool are not left with code alone. The document
  stays code until the reader asks for it.
- The frame has an opaque origin (`sandbox` without `allow-same-origin`) and a document
  policy that admits no network, so a page cannot read the console or reach an endpoint of
  its own. The policy is injected ahead of the document, so content preceding `<head>`
  cannot load before it applies.
- `present_openui` and `present_html` change nothing and are kept with the turn, so a
  follow-up can refine what was drawn.
- Code rendering moved to highlight.js (through lowlight) in one shared `CodeBody`:
  transcript fences, call arguments, page source and static snippets highlight the same
  way, and `hljs-` class names keep application styles off tokens. Startup JavaScript is
  unchanged and the Prism chunk the previous highlighter pulled is gone.

## Scheduled update checks and plugin update reminders

- **Update checks are scheduled from settings.** OMC Settings → Update checks sets the
  sweep interval from 15 minutes to 24 hours, hourly by default. The sweep reads the
  preference on every tick, so a change applies without a restart.
- **GitHub is configured once.** Release and star-count reads use the gateway's own
  `server.github-token` (Configuration → Access & Auth), resolved server-side and cached for
  five minutes. A rejected token is reported by name; an exhausted budget, including a 429,
  is reported and retried on the next sweep.
- **Reminders are pushed.** `GET /management/system/live` is a signal-only stream that
  announces when a check records its outcome and when the plugin sweep finishes. The
  navigation dot re-reads on that signal, re-reads once when the stream reopens, and keeps
  the hourly re-read as a fallback for deployments without the stream. Usage live updates
  share the same channel implementation.
- **Installed plugins are checked too.** The sweep reads the plugin store once at startup
  and on the same interval, and the Plugin Management entry carries the same amber dot for
  available plugin updates. Source-matched observations stay authoritative, notices survive
  source failures, and removed copies are cleared.
- **The installed list is reorderable.** Drag and keyboard ordering save display order in
  the `omc_plugin_order` preference, preserved across filtering and reloads and independent
  of the gateway's plugin loading order.
- **Available updates stand out.** An available update is a labelled text button in the
  row's action cluster naming the release it offers (`Update to v0.1.4`), in the same
  warning ink as the navigation reminder, with a reserved slot so row controls do not shift.
- Phone layouts gain full-width search and descriptions, right-aligned row controls, an
  inline reorder handle and a compact update-check button. The update-check spinner appears
  only for an explicit manual check; enablement changes and background registry refreshes
  stay independent.

## Credential identity and branding

- Credential identity has one home in `web/src/types/credentialIdentity.ts`: the issuing
  portal when a plugin declares it, over the credential family. Request records, request
  details, routing cards, OAuth workspace sections, provider filter tabs, the credential
  drawer, the model-rules drawer and the dashboard quota rows all come through it.
- The dashboard's credential quota panel previously filed every credential under its
  provider family and drew the whole plugin's logo. Quota rows now draw the issuing
  portal's mark, which distinguishes entries such as Qoder and Qoder CN.
- The issuing portal's name is shown alongside its artwork in request records, details,
  live routing and request-image exports, so a portal such as Workbuddy AI keeps its own
  name instead of a family alias. Legacy family fallbacks and built-in provider names are
  preserved, and routing behavior is unchanged.
- Artwork resolution no longer accepts portal evidence as a parameter: it walks only the
  keys the identity proves, so a dropped portal cannot silently reintroduce the family
  mark.

## Pricing

- A model CPA serves under a credential-scoped OAuth alias is now priced. The catalog read
  also resolves each file-backed credential's own `model_aliases` — what the console's
  OAuth model-rules drawer writes, and what CPA resolves before the provider's rules — and
  applies them ahead of that credential's provider-wide rules.
- The hidden upstream enters the catalog and the provider's pricing membership, so routed
  requests become billable and the price editor accepts the model the request row shows.
- Rules stay the credential's own: a sibling credential's rule never retargets this one's
  call point. An unreadable credential file refuses the snapshot instead of publishing a
  pruned catalog, so the last complete catalog and its rates stay in effect.
- Already-ingested requests stay unpriced, because prices lock at ingest.

## OAuth

- Terminal OAuth failures now return CPA's actionable reason after redaction and
  Unicode-safe truncation, bounded at 300 characters. Credential-bearing forms, callback
  parameters, session identity and email addresses are redacted before truncation.
- Successful and pending status reads carry only the normalized status.

## Upgrade notes

- Back up `.env` and your SQLite database or volume before upgrading; refer to
  `docs/ops/sqlite-operations.md`.
- Database migrations: none. Both new settings are preference rows
  (`omc_update_check`, `omc_plugin_order`) and need no schema change.
- The background sweep now runs hourly by default instead of every six hours, and its
  interval comes from OMC Settings → Update checks rather than a fixed period. A deployment
  that wants the previous cadence selects six hours.
- Configure `server.github-token` on the configuration page to raise the GitHub budget for
  both processes. Without it the checks continue unauthenticated.
- `OMCPA_UPDATE_CHECK_ENABLED` still enables or disables the background release and plugin
  update checks.
- Container images are available on Docker Hub as `wiziscool/oh-my-cpa:v0.3.25` and
  `wiziscool/oh-my-cpa:0.3.25`.
